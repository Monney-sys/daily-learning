# 应急响应速查

> 日志排查 / 入侵取证 / 弱口令检索。命令抽取自 daily-learning 四篇应急响应笔记,仅收录笔记中出现的命令与工具调用。
> 查法:先 `工具 -h`,再翻本文件;找不到问 Hermes。

## 日志排查(Win/Linux)

### Windows 事件日志(登录/爆破)
- **打开 Windows 事件查看器**: `eventvwr.msc` — 图形界面,安全(Security)日志里筛事件 ID;事件日志本体在 `C:\Windows\System32\winevt\Logs\` (源:09-03OS应急)
- **RDP(3389)暴力破解排查认准两个事件 ID**: `4625`(登录失败)、`4624`(登录成功) — 都在安全日志里,用 LogFusion 或 eventvwr 按事件 ID 筛选即可统计爆破;Win 侧重点是"会查事件 ID" (源:09-03OS应急)
- **用 LogFusion 载入事件日志文件查看**: `LogFusion` — 图形工具载入后按事件归类/事件 ID/事件状态筛选(如 4624/4625),替代 eventvwr 的另一种姿势 (源:09-03OS应急)
- **注意 IIS/PowerShell/Sysmon 等补充日志源**: IIS 日志默认在 `C:\inetpub\logs\LogFiles\`、PowerShell 操作日志事件 ID 4104、Sysmon(可选装) — 排查 Web 入侵/命令执行时别只盯系统事件日志 (源:09-03OS应急)

### Linux 认证日志(SSH 爆破五连查)
> 认证日志位置:CentOS/RHEL 在 `/var/log/secure`,Debian/Ubuntu 在 `/var/log/auth.log`——SSH 登录成败都在这,爆破排查主力文件 (源:09-03OS应急)

- **统计被暴力破解多少次(Failed password 出现次数)**: `grep -o "Failed password" /var/log/secure|uniq -c` — 先量化再往下查 (源:09-03OS应急)
- **输出爆破记录第一行(爆破开始时间)**: `grep "Failed password" /var/log/secure|head -1` (源:09-03OS应急)
- **输出爆破记录最后一行(爆破结束时间)**: `grep "Failed password" /var/log/secure|tail -1` — head/tail 两条合起来确认爆破时间范围 (源:09-03OS应急)
- **正则抽 IP 并计数排序,定位哪些 IP 在爆破**: `grep "Failed password" /var/log/secure|grep -E -o "(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)\.(25[0-5]|2[0-4][0-9]|[01]?[0-9][0-9]?)"|uniq -c | sort -nr` — 看谁最凶;正则已按 IP 段合法范围写的,原样复制 (源:09-03OS应急)
- **抽出被爆破的用户名字典(perl 正则取 for...from 之间字段)**: `grep "Failed password" /var/log/secure|perl -e 'while($_.=<>){ /for(.*?) from/; print "$1\n"; }'|uniq -c|sort -nr` — 名字一堆乱凑 = 脚本字典在扫 (源:09-03OS应急)
- **列出登录成功的日期/时间/用户/IP(查漏网之鱼,最关键一步)**: `grep "Accepted " /var/log/secure | awk '{print $1,$2,$3,$9,$11}'` — 有爆破成功 = 已被入侵,转入后门/账户排查;只有失败 = 被扫,改密+封 IP 即可 (源:09-03OS应急)
- **成功登录 IP 排行**: `grep "Accepted " /var/log/secure | awk '{print $11}' | sort | uniq -c | sort -nr | more` (源:09-03OS应急)

### Win 登录日志可视化(LogonTracer + Neo4j)
- **下载并解压 neo4j 图数据库**: `tar -zxvf neo4j-community-4.2.1-unix.tar` — JPCERTCC 的 LogonTracer 把 Win 安全日志登录事件导入 Neo4j 画登录关系图,爆破/横向登录一眼看穿 (源:09-04数据库应急)
- **装 Java11(neo4j 4.x 依赖)**: `sudo yum install java-11-openjdk -y` (源:09-04数据库应急)
- **放开 Bolt 监听允许外部访问(写入 neo4j.conf)**: `dbms.connector.bolt.listen_address=0.0.0.0:7687` — 云主机部署记得安全组/防火墙放行 7474/7687/8080 或直接关防火墙 (源:09-04数据库应急)
- **放开 HTTP 监听允许外部访问(写入 neo4j.conf)**: `dbms.connector.http.listen_address=0.0.0.0:7474` (源:09-04数据库应急)
- **前台启动 neo4j**: `./bin/neo4j console &` (源:09-04数据库应急)
- **拉 LogonTracer 源码**: `git clone https://github.com/JPCERTCC/LogonTracer.git` (源:09-04数据库应急)
- **装 LogonTracer 依赖**: `pip3 install -r requirements.txt` (源:09-04数据库应急)
- **远程模式启动 Web 看分析结果**: `python3 logontracer.py -r -o 8080 -u neo4j -p <密码> -s <neo4j服务器IP>` — `-r/--run`=启动 web 应用,`-o`=web 端口默认 8080,`-s`=neo4j 地址,`-u/-p`=neo4j 账号密码 (源:09-04数据库应急)
- **导入本地 evtx 单机分析**: `python3 logontracer.py -e Security.evtx -z <UTC时区偏移> -u neo4j -p <密码> -s 127.0.0.1` — `-z` 为时区偏移,课程示例 `-z -13`(来历待查),官方 README 示例 `-z 9`=JST;实际取值以日志时区为准 (源:09-04数据库应急)
- **导出本机 Security 日志为 evtx 供导入**: `wevtutil epl Security C:/temp/Security.evtx` — 实操 LogonTracer 前先在 Win 上导一份真实登录日志 (源:09-04数据库应急)
- **浏览器访问查看登录关系图**: `http://<IP>:8080`(web_gui) — 内网玩法:把 evtx 拷到部署机导入即可,不必外网开端口 (源:09-04数据库应急)

## 入侵痕迹排查

### Windows 进程/执行痕迹取证(溯源"服务器卡顿"类)
- **查看内核级进程/驱动(比任务管理器深)**: `PCHunter64` — 查隐藏进程、可疑进程的路径/模块/网络连接,服务器异常卡顿时第一梯队工具 (源:09-02总框架)
- **列出用户运行过的 GUI 程序执行记录**: `UserAssistView` — 读注册表 UserAssist 键,还原"之前跑过什么程序" (源:09-02总框架)
- **解析 AppCompatCache 导出执行时间线 CSV**: `AppCompatCacheParser.exe --csv c:\temp -t` — MANDIANT 出品;`--csv c:\temp` 导出 CSV、`-t` 处理时区,还原系统执行过程序的时间线,和日志时间基线的"首次写入时间"互相印证 (源:09-02总框架)

### 后门木马排查与攻防演练(CrossC2 / geacon)
- **生成 Linux 平台 C2 后门(攻防演练,仅授权环境)**: `./genCrossC2.Linux 47.99.49.65 5566 null null Linux x64 C2` — CrossC2 是 CS Beacon 的 Linux 实现;参数 ≈ [C2 IP][端口][两个占位 null][平台 Linux][架构 x64][文件名 C2];流程:上传项目到服务端→给执行权限→配监听器→生成→运行后自查 (源:09-03OS应急)
- **自查异常监听端口/外连,揪后门**: `netstat -ntulp` — Linux 查后门第一步,看有无可疑端口监听与外连;配合网络监控工具、Windows 日志/执行记录交叉定位 (源:09-03OS应急)
- **CrossC2 / geacon 项目地址(学习参考)**: `https://github.com/gloxec/CrossC2`、`https://github.com/darkr4y/geacon` — 参考过程: `http://www.adminxe.com/1287.html` (源:09-03OS应急)

### 勒索病毒(WannaCry)应急
- **360 勒索病毒专题站(中毒表现说明+恢复/解密引导)**: `https://lesuobingdu.360.cn/` — WannaCry 特征:文件被加密改名(.WNCRY)、桌面弹勒索窗口/壁纸被改、445(SMB/MS17-010 永恒之蓝)横向扩散 (源:09-03OS应急)
- **No More Ransom(上传勒索信/样本识别家族+免费解密器)**: `https://www.nomoreransom.org/zh/index.html` — Europol+安全厂商联合站;处理顺序:断网隔离→识别家族→查免费解密器→评估可恢复数据(备份/卷影副本)→重装加固,别急着交赎金 (源:09-03OS应急)

### 自动化取证/应急工具箱
- **ir-rescue 取证采集脚本(Win 版)**: `ir-rescue-win.bat` — 项目 github.com/diogo-fernan/ir-rescue;纯批处理+内置命令+Sysinternals/NirSoft 三方工具,刻意不用 PowerShell/WMI 保兼容;按数据易失性顺序批量采集网络连接/进程/账户/计划任务/日志/自启动项 (源:09-04数据库应急)
- **ir-rescue 取证采集脚本(nix 版)**: `ir-rescue-nix.sh` — 需 bash4+;思路是读懂每段在收集什么→改成自己的工具箱,不只当黑盒跑 (源:09-04数据库应急)
- **Gscan Linux 主机应急一键取证**: `Gscan`(多重功能脚本) — 把"分析八项"(账户/端口/进程/网络/启动/服务/任务/文件/日志)一键收集输出;具体功能清单/用法课程未展开,与 ir-rescue 同类按平台选型 (源:09-03OS应急)

## 数据库日志

### MySQL 通用查询日志(general_log)排查
> general log 记录所有到达的 SQL——注入 payload 和登录尝试都会留下,是数据库层排查主力;但全量记录涨得快,排查完务必关掉,生产常开的是 binlog/慢查询 (源:09-04数据库应急)

- **① 看当前 general_log 开关状态与日志文件位置**: `show variables like '%general%';` (源:09-04数据库应急)
- **② 开启通用查询日志(排查期临时开)**: `SET GLOBAL general_log = 'On';` (源:09-04数据库应急)
- **③ 指定 general log 文件路径**: `SET GLOBAL general_log_file = '/var/lib/mysql/mysql.log';` — 三连后随便执行几条 SQL + 制造一次失败登录,看日志记了什么 (源:09-04数据库应急)
- **分析完关闭 general log(踩坑必做)**: `SET GLOBAL general_log='Off';` — 防止日志文件拖垮业务 + 记录被持续写脏;爆破特征 = 海量 Access denied/失败连接,注入特征 = union/select 拼接、报错回显等异常语句 (源:09-04数据库应急)

### MSSQL / Oracle
- **MSSQL 排查分"查看+跟踪"两步**: 查看错误日志/登录审核分析登录行为;配置跟踪(Profiler/服务器端跟踪)分析 SQL 语句、对象变更、登录等具体操作 — Profiler 配置与登录日志位置等落地细节待对照视频补全 (源:09-04数据库应急)
- **Oracle 走审计日志+告警日志路线(猜测待验证)**: 课程标题含 Oracle 但截图未展开,手法待对照视频确认 (源:09-04数据库应急)

## 漏洞口令检索工具(日志没了→模拟渗透自查)

> 适用场景:日志被删/没价值信息、没分析思路时——假设自己是攻击者,从攻击面重打一遍,找到能进来的洞 = 还原攻击入口 (源:09-04数据库应急)

### 系统层漏洞自查(补丁→EXP)
- **Windows 补丁比对 CVE 库,列可利用漏洞(WindowsVulnScan)**: `D:\Myproject\venv\Scripts\python.exe cve-check.py -C -f KB.json` — `-f KB.json` 传本机已装补丁 KB 列表,`-C` 比对 CVE 库;缺哪个补丁 ≈ 可能从哪个洞进 (源:09-04数据库应急)
- **Linux 内核 EXP 提示**: `./linux-exploit-suggester.sh` — 读内核版本/发行版,提示可尝试的内核 EXP,自查系统层攻击入口 (源:09-04数据库应急)

### 应用/服务层漏洞自查
- **列 Windows 已装软件清单**: `Get-WmiObject -class Win32_Product` — PowerShell 执行,知道装了什么才能猜攻击者用什么洞 (源:09-04数据库应急)
- **Linux 主机枚举(内核/服务/SUID/计划任务/敏感文件)**: `LinEnum.sh` — 应用/服务漏洞自查用 (源:09-04数据库应急)
- **按应用服务协议检索公开 EXP**: `searchsploit weblogic` — 通用写法 `searchsploit <服务名>`,如 weblogic;先定指纹再查 EXP 收窄范围 (源:09-04数据库应急)

### 弱口令自查
- **SNetCracker 超级弱口令检查工具(Win)**: `SNETCracker` — 探针或人工获取判断,自查 SSH/RDP/SMB/数据库等协议有无弱口令;仅限授权环境(呼应 SSH/RDP 爆破排查,口令是攻击者常走的路) (源:09-04数据库应急)
