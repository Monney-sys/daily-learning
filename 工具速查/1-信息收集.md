# 信息收集速查

> 从 daily-learning「信息搜集方法论 / 漏洞发现系列①~④ / DC-1 实战」笔记(2026-07-22 ~ 2026-08-15)抽取的**扫描、探测、枚举类命令速查**。命令一律原样照抄笔记(含占位符),备注写何时用/踩坑,行尾 (源:xxx) 缩写对应文末「来源笔记」。仅限授权环境(靶场/CTF)使用。

## 主机存活与端口扫描

### netdiscover(主机存活)
- **ARP 扫描定位同网段存活主机/靶机 IP**: `sudo netdiscover -r 192.168.96.0/24` — DC-1 实战用它找到靶机 192.168.96.134;ARP 层探测防火墙一般拦不到,内网先扫存活、再扫端口 (源:08-15DC1)

### nmap(端口扫描)
- **端口 + 服务版本 + 默认脚本综合扫描(实战实例)**: `nmap -sV -sC 192.168.96.134` — DC-1 一把扫出 22 SSH + 80 HTTP(Apache 2.2.22),老系统直接按版本查历史漏洞;-sC 跑默认 NSE 脚本信息更全但更慢 (源:08-15DC1)

### masscan / naabu(快速全端口)
- **masscan**: 全端口扫描,速度快;适合先全端口摸一遍、再用 nmap 精扫服务版本(笔记未给完整命令,和 nmap 对比练速度是 08-14 待实践项) (源:07-26信息搜集/08-14服务协议)
- **naabu**: Go 实现的全端口扫描器,轻量快速,可作 masscan 的替代 (源:07-26信息搜集)

## 服务指纹与操作系统识别

### nmap(服务版本与 OS 指纹)
- **服务版本探测**: `nmap -sV` — 识别端口上运行的具体服务及版本;扫到端口先 -sV 定服务,再对号查漏洞库(如 6379 → Redis 查未授权);用时补目标 IP (源:07-26信息搜集)
- **操作系统指纹(基础写法)**: `nmap -O` — TCP/IP 栈指纹匹配判断 OS,确定 Windows/Linux 决定后续漏洞方向 (源:07-26信息搜集)
- **操作系统指纹(带目标写法)**: `nmap -O <目标IP>` — 07-23 笔记写法;需 root/管理员权限,准确度高 (源:07-23OS第三方)

### ping(TTL 初判)
- **TTL 值快速判断 OS**: `ping <目标IP>` — TTL≈64 为 Linux/macOS,≈128 为 Windows,≈255 为网络设备;只是粗略判断,经过 NAT/代理 TTL 会变 (源:07-23OS第三方)

### 综合扫描器(图形化/商业,一句话定位)
- **Goby**: 资产发现 + 漏洞扫描一体化,图形化,红队常用,扫出资产直接挂漏洞库比对 (源:08-13OS漏洞发现)
- **Nessus**: Tenable 商业漏洞扫描器,漏洞库全、报告专业,企业标配 (源:08-13OS漏洞发现)
- **OpenVAS**: Nessus 的开源替代(Greenbone 维护) (源:08-13OS漏洞发现)
- **Nexpose**: Rapid7 商业漏洞扫描器,与 Metasploit 同厂,扫完无缝对接利用 (源:08-13OS漏洞发现)

## 域名与子域名

### subfinder / amass(子域名枚举)
- **子域名枚举(subfinder)**: `subfinder -d example.com` — 被动收集,基于证书透明度等数据源,快且动静小 (源:07-23OS第三方)
- **子域名枚举(amass)**: `amass enum -d example.com` — OWASP 出品,数据源全、枚举深度大,速度较慢 (源:07-23OS第三方)
- **ksubdomain / OneForAll / Layer**: 字典爆破类子域工具,爆破速度取决于字典质量——ksubdomain 无状态发包最快、OneForAll 综合收集、Layer 是 Windows 图形化 (源:07-26信息搜集)
- **子域名验证与截图**: EyeWitness / gowitness — 多线程 HTTP 探活(200/403/301)并对存活子域截图留存 (源:07-26信息搜集)

### 证书透明度(CT)与第三方平台
- **crt.sh 证书透明度查询**: `curl -s "https://crt.sh/?q=%.example.com&output=json" | jq .` — 不接触目标即可拿历史子域名;URL 里 % 是通配符,响应 JSON 用 jq 格式化看 (源:07-23OS第三方)
- **Censys / SecurityTrails / VirusTotal / DNSdumpster**: 聚合 DNS/证书数据的第三方平台,免费额度够用;查历史子域/解析记录常用 (源:07-26信息搜集)

### DNS 记录与域传送
- **DNS 域传送漏洞探测**: `dig axfr @dns-server domain.com` — 极少见,但一旦存在直接全量泄露子域;@ 后填目标 NS 服务器地址 (源:07-26信息搜集)
- **查 MX 记录(邮件服务器/网关品牌)**: `dig example.com MX` — 判断自建邮服还是腾讯企业邮等;配合邮件头 Received 字段可能挖出真实 IP (源:07-23OS第三方)
- **nslookup 查 MX(Windows 自带)**: `nslookup -type=MX example.com` — dig 不可用时用 (源:07-23OS第三方)
- **指定国外 DNS 解析**: `nslookup example.com 8.8.8.8` — Google DNS;部分 CDN 只加速国内,国外解析结果可能直指真实 IP (源:07-23OS第三方)
- **指定国内 DNS 解析对比**: `nslookup example.com 223.5.5.5` — 阿里 DNS;与国外解析结果对比,判断是否套了 CDN (源:07-23OS第三方)
- **搜索引擎子域语法**: `site:*.example.com` — Google/Bing 收录的子域名,被动收集无痕 (源:07-23OS第三方)

## 目录与敏感文件

### dirsearch / gobuster / ffuf(目录扫描)
- **dirsearch**: 目录/文件扫描主力,字典全、输出友好;目录型站点(主站下一目录一个系统,如 xxx.com/blog)先扫隐藏目录,命中后台/备份/API 文档路径就是突破口 (源:07-26信息搜集/07-22中间件)
- **gobuster**: Go 实现,目录/子域名/DNS 爆破通用,速度快 (源:07-26信息搜集)
- **ffuf**: 快速模糊测试器,目录/虚拟主机/参数 FUZZ 通用 (源:07-23OS第三方)

### .git / 源码泄露提取
- **GitHack**: 服务器 .git 目录暴露时下载整站源码——配置文件(数据库密码/API Key/哈希)一把梭 (源:07-22中间件)
- **dvcs-ripper**: 同类工具,提取 .git/.svn/.hg 等版本控制泄露 (源:07-22中间件)

### Web 指纹识别与综合扫描器
- **WhatWeb**: 命令行指纹识别工具,CMS/框架/中间件一键识别 (源:07-22中间件/07-23OS第三方)

- **OWASP ZAP**: 免费开源 Web 综合扫描器 (源:08-13Web漏洞发现)

### WAF 识别
- **WAF 指纹识别**: `wafw00f` — 支持 150+ 种 WAF 指纹;识别出 WAF 后再谈绕过(分块传输/编码等),同时控制扫描频率防封 (源:07-26信息搜集)
- **WAF 手动试探 Payload**: `/index.php?id=1' OR '1'='1` — 观察拦截页特征/返回状态码(403/406/501)/Cookie 标记(__cfduid = Cloudflare) (源:07-26信息搜集)

## APP 与接口资产

### 抓包工具(http/https 与其他协议)
- **Burpsuite**: 抓包/改包/重放一体;APP 手机设代理指向 Burp,https 需装 CA 证书;遇到 SSL Pinning(证书固定)的 APP 普通代理抓不到,得靠逆向绕过 (源:08-14APP漏洞发现)
- **Charles / Fiddler**: 图形化抓包——Charles 看请求树/响应体直观,调试 API 常用;Fiddler Windows 老牌、脚本扩展强;同类还有抓包精灵(手机端直抓)、HTTP Toolkit / Reqable / whistle (源:08-14APP漏洞发现)
- **Wireshark**: 通用协议分析,抓 TCP/UDP/自定义协议流量看报文结构——先抓包判断 APP 走 http 还是自定义协议,再决定用哪套工具 (源:08-14APP漏洞发现)

### APK 逆向(提取接口资产/兜底)
- **jadx**: APK 反编译成可读 Java 代码,提取硬编码 URL/Key/Secret,整理成「接口资产清单」逐个测 (源:08-14APP漏洞发现)
- **APKLeaks**: 专门提取 APK 内 URL/密钥 (源:08-14APP漏洞发现)
- **MobSF**: APP 自动化安全分析框架 (源:08-14APP漏洞发现)
- **apktool**: 解包 + 改 smali(去校验/绕 SSL Pinning/改逻辑/分析加密),流程:解包 → 改代码 → 重打包 → 签名 → 安装 (源:08-14APP漏洞发现)
- **smali 修改后重打包**: `apktool b` — 改完 smali 重打包 APK;坑:重打包后原签名失效,需 apksigner 重新签名 (源:08-14APP漏洞发现)
- **Frida / xposed 模块**: 加固 APP 脱壳、动态 hook 绕过证书固定/root 检测 (源:07-26信息搜集/08-14APP漏洞发现)
- **API 接口测试工具**: SoapUI PRO / WS-Attacker / Burp Suite — 按探针面(猜 /api、/v2/api-docs 找接口)→ 应用面(订单/支付/短信模块逻辑漏洞)→ 安全面 → 利用面过一遍 (源:08-14服务协议)

## 黑暗引擎、CDN 绕过与真实 IP

### FOFA 查询语法
- **按域名搜子域**: `domain="xxx.com"` (源:07-26信息搜集)
- **按证书匹配**: `cert="xxx.com"` — 证书里带目标域名的资产(子域/旁站) (源:07-26信息搜集)
- **按标题关键字**: `title="后台管理"` — 找后台/管理系统 (源:07-26信息搜集)
- **按页面内容**: `body="技术支持"` (源:07-26信息搜集)
- **按响应头匹配**: `header="Server: nginx"` (源:07-26信息搜集)
- **C 段搜索**: `ip="1.1.1.1/24"` (源:07-26信息搜集)
- **协议 + 国家组合**: `protocol="redis" && country="CN"` — 例:全 CN Redis 服务,批量找未授权 (源:07-26信息搜集)
- **多条件组合示例**: `title="某某后台管理系统" && country="CN"` — && 可叠加 title/body/cert/ip 等条件 (源:07-23OS第三方)
- **证书通配示例**: `cert="*.example.com"` (源:07-23OS第三方)
- **body 特征字符串示例**: `body="<唯一特征字符串>"` — 拿网站独有特征对 IP 段全匹配,CDN 绕过/找真实 IP 用 (源:07-23OS第三方)

### Shodan 查询语法
- **搜相同 SSL 证书(找真实 IP)**: `ssl:"<证书序列号>"` — 对 IP 段 SSL 扫描匹配证书 CN/SAN (源:07-23OS第三方)
- **搜相同 HTTP 标题**: `http.title:"<页面标题>"` (源:07-23OS第三方)
- **ZoomEye / Hunter / Censys**: 同为网络空间搜索引擎——ZoomEye(知道创宇,Web 资产覆盖好)、Hunter(奇安信,国内资产较准)、Censys(证书/域名搜索强) (源:07-26信息搜集)

### GitHub 与搜索引擎
- **GitHub 搜源码泄露**: `"target.com" password` — 或 `"target.com" api_key`;监控目标域名/内网地址,找员工误传的配置、密钥、内部文档 (源:07-26信息搜集)

### CDN 绕过与真实 IP
- **hosts 绑定直连源站**: 格式 `<真实IP>  www.example.com`(例 `192.168.1.100  www.target.com`)— 拿到真实 IP 后改 hosts 绕过 CDN 访问,测完记得删;浏览器可能仍走 CDN 缓存,建议无痕模式/curl 验证 (源:07-23OS第三方)
- **Windows 刷新 DNS 缓存**: `ipconfig /flushdns` — 改完 hosts 生效 (源:07-23OS第三方)
- **Linux 刷新 DNS 缓存(systemd)**: `sudo systemctl restart nscd` (源:07-23OS第三方)
- **Linux 刷新 DNS 缓存(init 系)**: `sudo /etc/init.d/dns-clean` (源:07-23OS第三方)
- **macOS 刷新 DNS 缓存**: `sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder` (源:07-23OS第三方)
- **多地 ping / 全球节点访问平台**: ping.pe / 17ce.com / itdog.cn — 不同地区解析到不同 IP ≈ 有 CDN;用国外节点请求可能直接回源 (源:07-26信息搜集/07-23OS第三方)
- **DNS 历史记录平台**: SecurityTrails(securitytrails.com)/ ViewDNS.info(viewdns.info/iphistory/)/ DNSdb(dnsdb.io) — 查绑定 CDN 之前的真实 IP (源:07-23OS第三方)
- **邮件服务查真实 IP**: 发信/找回密码邮件源码看 Received 头与 X-Originating-IP 字段,邮件验证链接可能直指真实服务器 (源:07-23OS第三方)

## 其他:漏洞检索与实战枚举(DC-1)

### 漏洞库 / exploit 检索
- **本地查 exploit 与对应 CVE**: `searchsploit <关键词>` — Exploit-DB 本地命令行版,秒查;老系统 90% 的洞有现成代码 (源:08-13OS漏洞发现)
- **漏洞平台**: Exploit-DB(全球最全利用库)/ CNVD(国内官方)/ Seebug(知道创宇,含利用情报)/ 1337day(国外 0day)/ Packetstorm(老牌资料站)——查「框架/CMS + 版本」关键词,指纹对了平台才有效 (源:08-13OS漏洞发现/08-13Web漏洞发现)

### 配置与凭据枚举(DC-1 实战)
- **CMS 配置文件挖数据库凭据**: `cat /var/www/html/sites/default/settings.php | grep -iE "database|password|user"` — DC-1 从 Drupal settings.php 挖出 deuser/R0ck3t;每个 CMS 都有 config 文件,先找它 (源:08-15DC1)
- **连库枚举表结构**: `mysql -u deuser -p'R0ck3t' drupaldb -e "show tables;"` — 坑:`mysql -p` 与密码之间不能有空格,`-p'密码'` 必须紧贴否则被当库名;users 表里有 admin 的 Drupal7 hash($S$ 格式) (源:08-15DC1)
- **hashcat 破 Drupal7 hash(宿主机 GPU 跑)**: `hashcat -m 7900 -a 0 admin.hash rockyou.txt` — Drupal7 = 7900 模式;坑①Kali 虚拟机 GPU 报 "Not enough device memory",改用宿主机 RTX 4060 跑(33,619 H/s 约 1 分钟出);坑②hash 里的 `$S$` 会被 bash 当变量展开,写 hash 文件用单引号 `echo '$S$...'` (源:08-15DC1)
- **SUID 读 /etc/shadow 拿 root hash**: `find /etc -name shadow -exec cat {} \; 2>/dev/null` — DC-1 里借 SUID find 读 shadow,root hash 是 $6$(sha512crypt) 格式 (源:08-15DC1)

### 系统权限枚举与交互(DC-1)
- **枚举 SUID 文件(找提权点)**: `find / -perm -4000 2>/dev/null` — 找属主 root 带 s 位的程序;DC-1 中 /usr/bin/find 有 SUID(rws) 是关键考点 (源:08-15DC1)
- **验证 SUID 是否生效**: `find / -exec whoami \; | head -5` — 输出 root 说明以 root 身份执行;坑:不加 `| head -5` 遍历全盘会刷屏;meterpreter 里 find 不可用,先 `shell` 进系统 shell (源:08-15DC1)
- **伪造 TTY 获得交互 shell**: `python -c 'import pty; pty.spawn("/bin/bash")'` — meterpreter 的 shell 不是 TTY,`su` 报 "must be run from a terminal" 时用它 (源:08-15DC1)
