# XSS 跨站脚本 ## 原理 - 用户输入被原样拼入 HTML - 浏览器分不清“数据”和“代码” - 本质：数据和代码混淆 - 和 SQL 注入同理，执行位置在浏览器 ## 分类 - 反射型 XSS - 恶意代码在 URL 参数 - 需要诱导点击 - 一次性，只影响点击者 - 服务器原样回显用户输入 - 存储型 XSS - 恶意代码存入数据库 - 不需要诱导点击 - 所有访问者都会中招 - 危害最大，漏洞挖掘首选 - DOM 型 XSS - 全程不经过服务器 - 前端 JS 危险 API 操作 DOM - innerHTML / document.write - 服务器日志无记录 ## 触发方式 - script 标签 - <script>alert(1)</script> - 标签事件 - <img src=x onerror=alert(1)> - <svg onload=alert(1)> - <body onload=alert(1)> - <input onfocus=alert(1) autofocus> - <details open ontoggle=alert(1)> - 伪协议 - <a href="javascript:alert(1)">点我</a> - <iframe src="javascript:alert(1)"> ## 注入位置 - HTML 正文 <p>输出</p> - HTML 属性 <input value="输出"> - JavaScript 中 var x='输出' - <a href="输出"> - URL 参数 / HTTP 请求头 - User-Agent / Referer / Cookie - hidden 表单字段 - 用 type="text" 覆盖 ## 绕过 WAF - 标签替换 - <script> 被封 → <img onerror> / <svg onload> - 大小写混淆 - <ScRiPt> / <iMg sRc=x OnErRoR=alert(1)> - 双写绕过 - <scr<script>ipt> - oonnerrorror → onerror - 编码绕过 - HTML 实体：ja... 用于 <a href> - URL 编码：%3Cscript%3E - 双重URL编码：%253Cscript%253E - Base64：eval(atob('xxx')) - Unicode 编码 - 空格替代 - %0a / %0d / %09 / /**/ - 括号绕过 - 反引号：alert\`1\` - onerror=alert;throw 1 - 关键词拆分 - eval('al'+'ert(1)') - window\['al'+'ert'](1) - String.fromCharCode(97,108,...) - 伪协议编码 - javascript: → ja...: ## HttpOnly - 原理 - Set-Cookie 加 HttpOnly 标记 - document.cookie 读不到该 Cookie - 防了什么 - ✅ 防“偷”Cookie - ❌ 不防“用”Cookie - 绕过思路 - fetch 自动带 Cookie（credentials:include） - 弹钓鱼窗骗用户输入密码 - 操控浏览器直接做操作 - 一句话 - HttpOnly 把“偷钥匙”变成“趁主人在家用钥匙” ## 平台 / 工具 - BeEF - 浏览器利用框架 - 注入 hook.js → 控制台操控浏览器 - 信息收集 / 社工 / 内网扫描 - XSS Hunter / ezXSS - Blind XSS 回连平台 - 自动截图、收集 Cookie/DOM - XSStrike / Dalfox - 自动化扫描 - Dalfox 快 + DOM XSS - XSStrike 精细 + WAF 分析 - F12 + Burp - 80% 的 XSS 是手工找的 ## 防御 - 输出编码（核心防线） - HTML 内容：htmlspecialchars(s, ENT\_QUOTES) - HTML 属性：同上 + 必须加引号 - JavaScript：json\_encode(s) - URL：urlencode(s) - HttpOnly Cookie - CSP（Content-Security-Policy） - script-src 'self' - 浏览器层面拒绝内联脚本 - 输入校验（第一道防线） - 白名单，拒绝不符合预期的数据 - SameSite Cookie - Strict：跨站不带 Cookie → 防 CSRF
