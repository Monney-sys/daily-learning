### 2.9 分块传输编码（Chunked Transfer-Encoding）

**原理**：HTTP/1.1 支持分块传输。在 chunk 边界处把恶意 Payload 切开，WAF 按 chunk 分别检测时看不到完整特征。

```http
# 正常请求体
Content-Disposition: form-data; name="file"; filename="shell.php"

# 分块传输
Transfer-Encoding: chunked

5\r\n
Conte\r\n            ← 第1个chunk，WAF 看到这一块没异常
5\r\n
nt-Di\r\n
5\r\n
sposi\r\n
...
```

> ⚠️ 现代 WAF 大多已**自动重组 chunk**，此方法对主流云 WAF 效果有限。但对自建/老旧 WAF 依然有效。

---

### 2.10 编码绕过

| 编码类型 | Payload | 说明 |
|----------|---------|------|
| **URL 编码** | `filename="shell%2ephp"` (%2e = `.`) | WAF 是否会在检测前 URL 解码？ |
| **双重 URL 编码** | `filename="shell%252ephp"` (%25 = `%`, 解码后变 `%2e`, 再解码变 `.`) | 绕过只做一次 URL 解码的 WAF |
| **Unicode 编码** | `filename="shell.php"` | 某些 WAF 不识别 Unicode |
| **Hex 编码** | `filename="=UTF-8?B?c2hlbGwucGhw?="` | MIME 编码文件名 |

### 2.11 换行与污染字符混入

```http
# 在 filename 值中插入换行
Content-Disposition: form-data; name="file"; filename="shell.p
hp"

# 插入 NUL 字符（不是真正截断，只是污染正则匹配）
Content-Disposition: form-data; name="file"; filename="shell\x00.php"

# 在 Content-Type 后塞不可见字符
Content-Type: multipart/form-data; boundary=----boundary\x0b\x0c
```

这些字符可能破坏 WAF 的正则引擎 → 跳过检测 → 后端清理后得到合法文件名。

### 2.13 解析差异 — 利用三个系统的认知不一致

**核心攻击面**：WAF、Web 服务器、文件系统对文件名的处理规则不同。

| 差异类型 | Payload | WAF | 后端 | 结果 |
|----------|---------|-----|------|------|
| **尾部空格** | `shell.php ` | 检测 `.php `（带空格） | Windows 去掉空格 → `.php` | 绕过 |
| **尾部点** | `shell.php.` | 检测 `.php.` | Windows 去掉点 → `.php` | 绕过 |
| `::$DATA` | `shell.php::$DATA` | 不认识此语法 | Windows NTFS → 忽略 `::$DATA` | 绕过 |
| 路径合并 | `shell.asp/../shell.php` | 检测最终 `.php` | 某些后端可能先处理 `.asp` | 情况复杂 |
| 斜杠方向 | `shell\.php` | 视 `\` 为文件名一部分 | Windows 视 `\` 为分隔符 | 绕过 |

---

### 2.14 条件竞争 — 比 WAF 快

**原理**：文件先完整上传到服务器临时目录 → WAF/后端检测 → 发现恶意则删除。在这之间的极小时间窗口内，文件已经可以被访问。

```
时间线：
│
├─ t0: 文件上传完成，存在临时目录
├─ t1: WAF 开始检测           ← 文件在这段时间内"裸奔"
├─ t2: WAF 检测完毕 → 删除    ← 你要抢在 t2 前访问
│
攻击：在 t0~t2 之间不断请求 shell.php
```

```python
# 攻击者视角：两个并发线程
# 线程 1：不停上传 webshell
# 线程 2：不停尝试访问 webshell
# → 总会碰上一次"上传完成但还没删除"的时刻
```

### 2.15 绕过总结速查表

| 类别 | 核心思路 | 一句话 |
|------|----------|--------|
| **数据溢出** | 超出 WAF 检测上限 | 文件名塞几千个字符，恶意后缀放最后 |
| **符号变异** | 混淆 WAF 的语法解析 | 引号/分号/反斜杠/流特性 |
| **数据截断** | WAF 看完整 string，后端只看前半 | `%00` / `%0a` / `?` / `#` 切断 |
| **重复数据** | WAF 取 A 值，后端取 B 值 | 两个 `filename` 参数，放个无害的在前 |
| **大小写** | 正则没开 `(?i)` | `.Php` / `.PHP` |
| **CD 变形** | 畸形 Content-Disposition | 去引号/加空格/换行 |
| **MIME 欺骗** | 伪装成图片 | `Content-Type: image/jpeg` |
| **内容混淆** | 代码变形绕关键字 | 字符串拼接/base64/ASCII 编码 |
| **解析差异** | 三个系统理解不一致 | Windows 尾部空格/点/`::$DATA` |
| **条件竞争** | 和删除赛跑 | 并发上传 + 并发访问 |

## 三、防御方案（纵深防御）

### 3.1 后端校验（核心防线）

| 层级 | 措施 | 一句话 |
|------|------|--------|
| **后缀白名单** | 只允许 `.jpg .png .gif .pdf .docx` 等必要格式，不在白名单一律拒绝 | 白名单优于黑名单 |
| **文件重命名** | 上传后用 UUID/时间戳 随机重命名，扩展名由后端强制指定 | 用户提供的文件名**不可信** |
| **MIME 检测** | 校验文件真实 MIME（`finfo_file()`），不只信 `Content-Type` 头 | 客户端发来的 MIME 不可信 |
| **文件头检测** | 前 N 字节须匹配声明的文件类型魔数 | `‰PNG` / `GIF89a` / `ÿØÿ` |
| **完整性检测** | 对整个文件做格式校验（如图片能否正常 `getimagesize()`） | 防止"图片头 + webshell 体" |
| **内容扫描** | `function check_file()` 自定规则 + 调用杀毒引擎 | 拦截混淆代码 |

### 3.2 服务器层加固

| 措施 | Apache 配置 | Nginx 配置 |
|------|------------|------------|
| **上传目录禁脚本执行** | `php_admin_flag engine off` | `location /uploads/ { location ~ \.php$ { deny all; } }` |
| **上传目录在 Web 根外** | 路径不在 `/var/www/html/` 下 | 同左 |
| **文件权限** | Web 用户只有写权限，无执行权限 | 同左 |
| **禁用危险文件解析** | 封 `.htaccess .user.ini` 等配置文件上传 | 同左 |
| **文件大小限制** | `LimitRequestBody` | `client_max_body_size` |

### 3.3 WAF 层（辅助）

| 产品/方案 | 适用场景 |
|-----------|----------|
| **宝塔 WAF** | 个人/VPS 用户，部署简单，免费版够用 |
| **阿里云 WAF / 腾讯云 WAF** | 企业站，云原生集成 |
| **安全狗** | Windows Server 环境 |
| **ModSecurity + OWASP CRS** | 自托管，开源，可定制规则 |
| **CloudFlare WAF** | 海外站/CDN 场景 |

> ⚠️ WAF 是**最后一道防线**，不能替代后端校验。攻击者绕 WAF 只是时间问题，但好的后端校验能让你即使 WAF 被绕过也不出事。

### 3.4 防御分层总结

```
第一层：WAF（粗筛，拦住脚本小子的扫描器）
    ↓ 被绕过
第二层：后端白名单 + 文件重命名（核心防线）
    ↓ 被绕过
第三层：内容检测 + 格式校验（拦住图片马）
    ↓ 被绕过
第四层：上传目录隔离 + 禁止脚本执行（最后防线：即使 webshell 落盘也无法执行）
```

### 4.2 WAF 绕过实战测试思路

1. **先不用 WAF**：确认上传功能本身可被绕过（后端黑名单/白名单的弱点）
2. **再开 WAF**：部署宝塔/安全狗 → 尝试同样的 Payload → 哪些被拦？
3. **递进式测试**：
   ```
   正常后缀 (.php)        → 肯定被拦（基线）
   大小写 (.Php)           → 测试 WAF 正则是否完整
   Content-Type 欺骗      → 测试 WAF 是否只看 MIME
   数据截断 (%00)         → 测试 WAF 的解析边界
   文件内容混淆           → 测试 WAF 的内容检测深度
   数据溢出 (长文件名)    → 测试 WAF 的缓冲区限制
   ```
4. **观察 WAF 响应**：403？重定向？连接重置？不同响应告诉你 WAF 的拦截点在哪

## 五、总结

### 核心认知

> 文件上传绕过 WAF 的本质是**解析差异**——让 WAF 和后端对同一请求做出不同解释。

WAF 是可绕过的，不可依赖。真正的安全必须落在**后端代码**：
1. **白名单**后缀（不接受任何非业务需要的格式）
2. **文件重命名**（用户提供的文件名一律不可信）
3. **上传目录与执行隔离**（即使马落地也不能跑）
